# Specification: API Specifications & Contracts

Parent document: [docs/SPEC.md](../../docs/SPEC.md)

## 1. Route Versioning & Mirror Router
The internal Web UI uses the unversioned `/api/*` prefix and is authenticated by the session cookie. The external programmatic routes (token-authenticated ingestion, token verification, maintenance, metrics, prune and vacuum, log queries, alert history) and the MCP transport are served under `/api/v1/*`. The cookie-authenticated internal routers (auth, logs, settings, aliases, drop rules, saved views, notifications, alerts, system, AI, API tokens, Docker hosts) are NOT mirrored under `/api/v1/*`; requests to those paths return `404`. Use the canonical `/api/*` paths for them.

Every internal route requires the session cookie and returns `401` without a valid one, except `POST /api/auth/setup`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/status`, `GET /api/health` and `GET /api/system/version` (without `refresh`). Mutating internal calls also need `X-Requested-With` (otherwise `403`, see `docs/spec/security.md`), and FastAPI validation failures on query parameters or bodies return `422`. A few routes keep hidden aliases that are left out of the OpenAPI document: `GET /api/alerts/export`, `GET /api/alerts/{rule_id}/export`, `POST /api/alerts/import`, `POST /api/alerts/maintenance/sessions/{session_id}/disable` and `PUT /api/alerts/maintenance/schedules`.

The OpenAPI document (`/openapi.json`, `/docs`) declares an HTTP Bearer security scheme on the token-authenticated routes so `/docs` offers an Authorize button. The API documentation needs the web login: `/docs` and `/redoc` redirect to the login page (`302` to `/`) without a session cookie, and `/openapi.json` returns `401`; `/openapi.json` also accepts any valid API token (any scope) in `Authorization: Bearer`. Swagger UI and ReDoc are served by LogShed itself from `/docs-assets/` (no CDN, no Google Fonts), and `ENABLE_API_DOCS=false` turns all three routes off. Token-authenticated REST and ingestion responses return `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset` headers. MCP responses carry them only on `429`. Every `429` (token rate limits, the login and AI limits, and the prune and vacuum cooldowns) also adds `Retry-After` in whole seconds (see `docs/spec/security.md`). The `Bearer` scheme name is accepted in any letter case (RFC 7235). Every token-authenticated route can return `401` (missing, unknown or expired token), `403` (insufficient scope) and `429` (rate limit); FastAPI validation failures on query parameters or bodies return `422`.

### 1.1 Partial Updates
`PUT` updates and `POST /api/settings` change only the fields that are sent: a field that is absent from the JSON body keeps its stored value. How a field that is present but `null` or `""` is treated depends on the field:
- Optional filter or pattern fields clear the stored value when they are sent as `null` or `""`: alert rule `filter_app`, `filter_severity`, `match_pattern` and `channel_id`, and drop rule `source_pattern`, `app_pattern` and `severity_threshold`. Required fields of a rule (name, type, thresholds, window, cooldown, switches) treat `null` as "unchanged".
- Docker host `ca_cert`, `client_cert` and `client_key` keep the stored value when absent or `null`, and clear it when sent as `""`.
- Settings: `ai_base_url` can be cleared by sending `""`. A masked secret (`"********"`) means "keep the stored value", so a client can send back what `GET /api/settings` returned without overwriting a key.

## 2. Query Pagination & Evaluation Capping
When searching or listing log records via `GET /api/logs`, the response returns a `LogListResponse` payload containing:
- `logs`: Array of `LogEntry` records matching query filters.
- `total`: Total count of matching records up to the evaluation ceiling.
- `limit` and `offset`: The page size and offset that were applied (`limit` defaults to 100, maximum 1000).
- `total_capped`: Boolean flag indicating whether the total count was capped at the evaluation limit (`max(1001, offset + limit + 1)`). To prevent full-table scan bottlenecks on vast datasets under broad filters, SQLite limits the count calculation. When `total_capped` is true, the user interface displays a count indicator like `1,000+` or `(capped)` rather than executing expensive exhaustive table scans.

### 2.1 Time Filters
`from` and `to` on the web UI log routes, the REST API (`/api/v1/logs`, `/api/v1/logs/count`) and the MCP tools accept an ISO-8601 timestamp or a relative value:
- A duration counted back from now: a number and a unit (`30s`, `15m`, `1h`, `24h`, `7d`, `2w`).
- `since_midnight` or `today`: 00:00 today in the server time zone (`TZ`).
- `yesterday`: 00:00 on the previous local date in the server time zone.

Midnight is built from the local date, so days with a daylight saving change stay correct. All values are converted to UTC before they are compared with stored timestamps. An unknown value returns `422`.

### 3.1 Model Context Protocol (MCP) Capabilities
LogShed provides an integrated Model Context Protocol (MCP) server that enables external AI agents (Claude Desktop, Cursor, Antigravity, Windsurf) to investigate incidents and manage maintenance windows.

* **Transport Modes:**
  * **Streamable HTTP (`/mcp` and `/api/v1/mcp`):** Standard transport for modern MCP clients connecting over HTTP without separate SSE session handshakes. Requires an API token with `logs:read`, passed via `Authorization: Bearer`.
  * **Network SSE (`GET /api/v1/mcp/sse` + `POST /api/v1/mcp/messages`):** Used by IDEs with native SSE transport or Claude Desktop via `mcp-proxy` (which reads the token from its `API_ACCESS_TOKEN` environment variable and sends it as `Authorization: Bearer`). Requires an API token with `logs:read`. A session is bound to the token that opened it; revoking that token closes its open streams.
  * **Token placement:** Every MCP HTTP route accepts `Authorization: Bearer <token>`, or a raw token as the whole `Authorization` value. A `?token=` query parameter is refused with `401` unless `MCP_ALLOW_QUERY_TOKEN=true`, a supported opt-in for MCP clients that cannot send headers (a warning is logged when it is used, because URLs end up in proxy access logs).
  * **Scopes:** Connecting needs only `logs:read`. Each tool and resource then checks its own scope and returns a tool error when it is missing: `logs:read` for `query_logs`, `get_log_context`, `count_logs`, `list_services` and `logshed://services`; `alerts:read` for `get_recent_alerts` and `logshed://alerts/active`; `system:read` for `get_system_metrics` and `logshed://system/metrics`; `maintenance:write` for `enable_maintenance` and `disable_maintenance`. Namespace wildcards and `*` work as for REST. The stdio transport has full access.
  * **Local Docker Stdio (`app.cli mcp`):** Used when Claude Desktop runs locally alongside the container (`docker exec -i logshed python -m app.cli mcp`).
* **Runtime Switch:** Controlled by the `enable_mcp` runtime setting (default `false`). When disabled, every MCP HTTP endpoint returns `403 Forbidden` (`detail: "Model Context Protocol is disabled in system settings"`) before the token is checked.
* **Tools Exposed:**
  * `get_system_metrics`: Snapshot of ingestion rates, error distributions, top error apps/hosts, active alert states, and maintenance status. Includes `udp_receive_errors`, the UDP datagrams the kernel dropped since the syslog listener started. Over stdio the live ingestion counters (including `udp_receive_errors`) are `null` and `live_counters_available` is `false`.
  * `list_services`: Discovery of distinct application names and host sources sending logs, plus bidirectional host-app mappings. At most 500 hosts and 500 apps are listed; `truncated` is `true` when the lists were capped.
  * `query_logs`: Search logs using SQLite FTS5 syntax with app, host, severity (named or numeric), relative time window (`"1h"`, `"24h"`), and timestamp filters. Compact by default (`include_raw: false`) with configurable field projections (`fields`, which silently drops names that are not log fields) to conserve context tokens, and keyset pagination (`cursor` and `next_cursor`) for paging through large result sets. `limit` defaults to 50 and is clamped to 200.
  * `get_log_context`: Fetch chronological surrounding log lines around a target log ID with compact projection support.
  * `count_logs`: Fast and token-efficient log count queries with optional grouping by severity, application, or source host (`group_limit` and `truncated` as on `GET /api/v1/logs/count`).
  * `get_recent_alerts`: Retrieve recent alert firing incident summaries, triggering log samples and maintenance window entries (`limit` defaults to 10 and is clamped to 50).
  * `enable_maintenance`: Activate an on-demand maintenance window to silence alerts or drop errors during planned maintenance (recorded with trigger `MCP`; input is validated against the same limits as `POST /api/v1/maintenance/enable` and invalid values return a tool error). `drop_errors` over MCP requires a `target_app` or `target_host`; global error drops stay available from the web UI and REST API.
  * `disable_maintenance`: Deactivate one maintenance session by `session_id`, or all active sessions when it is omitted. Returns the same keys as the REST endpoint: `terminated_sessions`, `remaining_active_sessions`, `active` and `server_time`. An unknown or already ended `session_id` is an error.
* **Redaction:** Every MCP tool and external REST log or alert endpoint passes log `message` and `raw` text, alert samples, and AI diagnosis text through `redactor.py` before returning it. Internal UI endpoints (`/api/logs`, `/api/alerts`) are not redacted. Redaction is best-effort and may not catch every secret.
* **Resources Exposed:**
  * `logshed://system/metrics`: Real-time system telemetry and error distribution.
  * `logshed://services`: Directory of applications and host sources.
  * `logshed://alerts/active`: Maintenance state (`maintenance_active`, `maintenance_until`, `log_handling`) and the 5 most recent incidents.
* **Prompts Exposed:**
  * `investigate_incident`: Step-by-step diagnostic workflow guiding AI agents through metrics inspection, log search, context retrieval, alert history, and root-cause determination (arguments `app_name`, `time_window`).
  * `safe_service_upgrade`: Deployment workflow that checks a service's logs, starts a `drop_errors` maintenance window targeted at it, verifies clean startup logs, and ends the window (arguments `service_name`, `duration_minutes`).

### 3.2 AI Stream Event Payloads
`POST /api/ai/diagnose/stream` and `POST /api/ai/audit/{audit_id}/follow-up/stream` return `text/event-stream`. Every event is one `data:` line holding a JSON object whose `stage` field names the event. The server also sends an SSE comment line, `: ping`, every 15 seconds while a model call is quiet, so reverse proxies do not close the connection; clients ignore it.

| `stage` | Fields | Sent |
| --- | --- | --- |
| `init` | `model`, `fallback_models` (list), `message` | First event of every stream |
| `calling` | `model`, `attempt`, `total_models`, `is_fallback`, `message` | Before each model call |
| `failover` | `failed_model`, `next_model`, `error`, `message` | When a model fails with a retryable error and the next fallback model is tried |
| `delta` | `content` (text chunk) | Follow-up stream only; after a `failover` the next model streams from the start |
| `complete` | `result` (`AiDiagnosisResponse` or `AiFollowUpResponse`) | Last event on success |
| `error` | `message` (redacted text) | Last event on failure |

Closing the connection cancels the running model call.
