# Specification: API Specifications & Contracts

Parent document: [docs/SPEC.md](../../docs/SPEC.md)

## 1. Route Versioning & Mirror Router
The internal Web UI uses the unversioned `/api/*` prefix and is authenticated by the session cookie. The external programmatic routes (token-authenticated ingestion, token verification, maintenance, metrics, prune and vacuum, log queries, alert history) and the MCP transport are served under `/api/v1/*`. The cookie-authenticated internal routers (auth, logs, settings, aliases, drop rules, saved views, notifications, alerts, system, AI, API tokens, Docker hosts) are NOT mirrored under `/api/v1/*`; requests to those paths return `404`. Use the canonical `/api/*` paths for them.

Every internal route requires the session cookie and returns `401` without a valid one, except `POST /api/auth/setup`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/status`, `GET /api/health` and `GET /api/system/version` (without `refresh`). Mutating internal calls also need `X-Requested-With` (otherwise `403`, see `docs/spec/security.md`), and FastAPI validation failures on query parameters or bodies return `422`. A few routes keep hidden aliases that are left out of the OpenAPI document: `GET /api/alerts/rules/export`, `GET /api/alerts/rules/{rule_id}/export`, `POST /api/alerts/rules/import`, `POST /api/alerts/maintenance/sessions/{session_id}/disable` and `PUT /api/alerts/maintenance/schedules`.

The OpenAPI document (`/openapi.json`, `/docs`) declares an HTTP Bearer security scheme on the token-authenticated routes so `/docs` offers an Authorize button. Token-authenticated REST and ingestion responses return `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset` headers, and `429` responses (including MCP) add `Retry-After` (see `docs/spec/security.md`). Every token-authenticated route can return `401` (missing, unknown or expired token), `403` (insufficient scope) and `429` (rate limit); FastAPI validation failures on query parameters or bodies return `422`.

## 2. Query Pagination & Evaluation Capping
When searching or listing log records via `GET /api/logs`, the response returns a `LogListResponse` payload containing:
- `logs`: Array of `LogEntry` records matching query filters.
- `total`: Total count of matching records up to the evaluation ceiling.
- `limit` and `offset`: The page size and offset that were applied (`limit` defaults to 100, maximum 1000).
- `total_capped`: Boolean flag indicating whether the total count was capped at the evaluation limit (`max(1001, offset + limit + 1)`). To prevent full-table scan bottlenecks on vast datasets under broad filters, SQLite limits the count calculation. When `total_capped` is true, the user interface displays a count indicator like `1,000+` or `(capped)` rather than executing expensive exhaustive table scans.

### 3.1 Model Context Protocol (MCP) Capabilities
LogShed provides an integrated Model Context Protocol (MCP) server that enables external AI agents (Claude Desktop, Cursor, Antigravity, Windsurf) to investigate incidents and manage maintenance windows.

* **Transport Modes:**
  * **Streamable HTTP (`/mcp` and `/api/v1/mcp`):** Standard transport for modern MCP clients connecting over HTTP without separate SSE session handshakes. Requires an API token with the `AI Assistant / MCP` scope bundle passed via `Authorization: Bearer`.
  * **Network SSE (`GET /api/v1/mcp/sse` + `POST /api/v1/mcp/messages`):** Used by IDEs with native SSE transport or Claude Desktop via `mcp-proxy` (which reads the token from its `API_ACCESS_TOKEN` environment variable and sends it as `Authorization: Bearer`). Requires an API token with the `AI Assistant / MCP` scope bundle.
  * **Token placement:** Every MCP HTTP route accepts `Authorization: Bearer <token>`, a raw token as the whole `Authorization` value, or a `?token=` query parameter.
  * **Local Docker Stdio (`app.cli mcp`):** Used when Claude Desktop runs locally alongside the container (`docker exec -i logshed python -m app.cli mcp`).
* **Runtime Switch:** Controlled by the `enable_mcp` runtime setting (default `false`). When disabled, every MCP HTTP endpoint returns `403 Forbidden` (`detail: "Model Context Protocol is disabled in system settings"`) before the token is checked.
* **Tools Exposed:**
  * `get_system_metrics`: Snapshot of ingestion rates, error distributions, top error apps/hosts, active alert states, and maintenance status.
  * `list_services`: Discovery of distinct application names and host sources sending logs, plus bidirectional host-app mappings.
  * `query_logs`: Search logs using SQLite FTS5 syntax with app, host, severity (named or numeric), relative time window (`"1h"`, `"24h"`), and timestamp filters. Compact by default (`include_raw: false`) with configurable field projections (`fields`) to conserve context tokens, and keyset pagination (`cursor` and `next_cursor`) for paging through large result sets. `limit` defaults to 50 and is clamped to 200.
  * `get_log_context`: Fetch chronological surrounding log lines around a target log ID with compact projection support.
  * `count_logs`: Fast and token-efficient log count queries with optional grouping by severity, application, or source host (`group_limit` and `truncated` as on `GET /api/v1/logs/count`).
  * `get_recent_alerts`: Retrieve recent alert firing incident summaries, triggering log samples and maintenance window entries (`limit` defaults to 10 and is clamped to 50).
  * `enable_maintenance`: Activate an on-demand maintenance window to silence alerts or drop errors during planned maintenance (recorded with trigger `MCP`; input is validated against the same limits as `POST /api/v1/maintenance/enable` and invalid values return a tool error).
  * `disable_maintenance`: Deactivate one maintenance session by `session_id`, or all active sessions when it is omitted.
* **Redaction:** Every MCP tool and external REST log or alert endpoint passes log `message` and `raw` text, alert samples, and AI diagnosis text through `redactor.py` before returning it. Internal UI endpoints (`/api/logs`, `/api/alerts`) are not redacted. Redaction is best-effort and may not catch every secret.
* **Resources Exposed:**
  * `logshed://system/metrics`: Real-time system telemetry and error distribution.
  * `logshed://services`: Directory of applications and host sources.
  * `logshed://alerts/active`: Maintenance state (`maintenance_active`, `maintenance_until`, `log_handling`) and the 5 most recent incidents.
* **Prompts Exposed:**
  * `investigate_incident`: Step-by-step diagnostic workflow guiding AI agents through metrics inspection, log search, context retrieval, alert history, and root-cause determination (arguments `app_name`, `time_window`).
  * `safe_service_upgrade`: Deployment workflow that checks a service's logs, starts a `drop_errors` maintenance window targeted at it, verifies clean startup logs, and ends the window (arguments `service_name`, `duration_minutes`).
