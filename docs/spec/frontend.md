# Specification: Frontend Specification (React + Vite + Tailwind)

Parent document: [docs/SPEC.md](../../docs/SPEC.md)

## 1. Overview & Architecture
The LogShed frontend is a responsive single-page web application built with React, Vite, and Tailwind CSS. The interface is tailored for dense, real-time log observation, incident investigation, rule configuration, and system administration. Production builds are bundled directly into `backend/app/static/` and served by FastAPI with HTML5 History API fallback routing to `index.html`.

Times are shown in the server time zone (`server_timezone` from `GET /api/settings`), the same zone the log stream and search presets use, falling back to browser time until settings load. This covers the log stream, alert history and incident details, "Last triggered" on alert rules, maintenance end and next-run times (also in the navbar banner), the prune cut-off, the digest's last run, the model cache time and API token dates. Date and time inputs use the same zone and show its name beside them: the Console custom From and To pickers (switching from "Today" to "Custom" fills From with midnight on the server clock) and the maintenance "Specific End Time" picker (`toLocalDatetimeInputString`, `fromLocalDatetimeInputString` and `startOfTodayIso` in `utils/formatters.ts`). A time the server clock shows twice (clocks going back) is read as its first occurrence, and a time it skips (clocks going forward) is moved forward by the length of the gap, as maintenance schedules are. While the zone is unknown (settings not loaded, or `server_timezone` is `null`) the inputs take browser time and say "browser time".

## 2. Navigation Hierarchy
The frontend implements single-page HTML5 History API routing across four top-level navigation destinations:
- **`/` (Logs / Console):** Live streaming log console with virtual scrolling, search, filters, saved views, and context inspection.
- **`/rules` (Rules & Alerts Hub):** Unified hub managing alert rules, ingestion drop rules, incident history, maintenance windows, and built-in canary presets.
- **`/storage` (Storage Metrics):** Storage metrics dashboard displaying database file sizes, host mount disk usage, 30-day volume trends, manual prune triggers, and database vacuum utilities. Lowering retention or purging expired data first shows a preview modal listing the logs, history items, metrics and AI audit records that would be deleted.
- **`/settings` (Settings & Aliases):** Application settings, AI provider configuration, notification channels, API & MCP access, advanced runtime options, and IP-to-Host alias management located at `/settings/aliases`. Top-level requests to `/aliases` automatically redirect to `/settings/aliases`.

A Settings save sends only the fields that differ from the saved settings (`components/settings/useSavedForm.ts`; the AI provider form compares each provider with its saved values). A value changed elsewhere since the page loaded, in another card or another browser, is shown in every field not being edited and is never written back.

Unsaved changes detection and browser exit guards prevent accidental loss of form inputs across settings tabs and modal dialogs. When the prompt holds back a link that leaves Settings (for example "View logs" on a host alias, which opens `/?source=<alias>`), Discard & Leave and Save & Continue open that exact URL, so its filters are kept.

## 3. Core Components & Views

### 3.1 Console Viewer (Live Stream - `/`)
* **Virtual List Implementation (`@tanstack/react-virtual`):**
  * Virtual list container capable of rendering 50,000+ log lines without DOM performance degradation.
  * Dynamic item measurement with parent scroll container integration.
* **Live Streaming & Flow Control:**
  * Real-time Server-Sent Events (SSE) stream consuming incoming log records. Closed immediately on `pagehide` (refresh or navigation, and reconnected on `pageshow` if restored from bfcache) and paused after 30 s while the tab stays hidden (`visibilitychange`), so idle background tabs do not stall reverse-proxy HTTP/2 connections. On return (with no `to` ceiling) the logs missed meanwhile are fetched first (`catchUpLiveLogs` in `useLogBuffer.ts`), then the stream reconnects, so live rows stay in time order. With auto-scroll on the list reloads. Scrolled back, the missed logs go through the live path (held or prepended with the scroll anchored, and counted in the "N new logs at top" banner), fetching up to 10 pages of 500 until one meets a row already listed; if none does, they are only counted, since joining them would leave a gap, and the list reloads once auto-scroll resumes.
  * Configurable auto-scroll operation with automatic pause detection when the operator scrolls upward. On phones the button reads "Scroll" (or "Paused") and the clear buffer button is left out, so the quick filters keep their room.
  * While paused, new rows join the top of the list and the scroll position moves down by their height, so the rows in view stay put. While the operator is scrolling (a finger on the list, or a scroll event in the last 150 ms, which covers the glide after a flick), new rows are held and counted in the "N new logs at top" banner instead, because phone browsers show a scroll position change during a drag or glide as a jump. Once scrolling stops they join in one batch with one correction. Rows held because the scrollback buffer is full wait for auto-scroll to resume.
  * The Paused button and the "N new logs at top" banner turn auto-scroll back on and scroll smoothly to the top. The scroll events on the way up do not pause it again, so new rows keep it going to the top; touching, wheeling, clicking or a cursor key hands the list back to the operator (or 1.5 s pass).
* **Desktop Columns:** The table (768 px and wider) has the columns checkbox (36 px), time (120 px), severity (65 px), host (130 px), app (130 px), message (the rest) and, with AI on, actions (60 px), in one grid the header and every row share (`LOG_GRID_COLS_WITH_AI` and `LOG_GRID_COLS_WITHOUT_AI` in `LogRow.tsx`). The time, host and app widths are the CSS variables `--col-time`, `--col-host` and `--col-app` on the box around the header and the list (`useColumnWidths`), so resizing restyles that box and no row re-renders; the grid's fallbacks are the defaults. Each of the three headings has a drag handle at its right edge (`ColumnResizeHandle`, 12 px wide inside the heading, with its line 6 px from the column's edge, so the line has 6 px clear of the next column's heading and of its own, which keeps 12 px of right padding): a focusable `role="separator"` (`aria-orientation="vertical"`, named "Resize Timestamp column" and so on, `aria-valuenow` the width in px with its `aria-valuemin` and `aria-valuemax`) in the WAI-ARIA window splitter pattern. A drag moves the column as the pointer moves without a React render and keeps the width on release (a move with no button held, or a lost pointer capture, ends the drag where it was); Left and Right change it by 8 px, Home and End go to the narrowest and widest, Enter or a double-click resets it. Each column has a minimum that fits its heading (time and host 72 px, app 112 px) and a maximum of 800 px, and the three are fitted to the header's width so the message column keeps at least 200 px (narrowing app, then host, then time, no lower than their minimums); a narrower window fits them again, and a wider one gives the chosen widths back. The widths are kept in this browser only (`localStorage` key `logshed.console.columnWidths.v1`, read and written through `utils/browserPrefs.ts`, where a missing, unreadable or out-of-range value means the default), and the key is removed when every column is back at its default. **Reset widths**, at the right of the MESSAGE heading, shows while any width differs from its default and puts all three back. Severity, checkbox and actions keep their width; the severity heading has the same line at its right edge as the resizable headings, with no handle. Phones show cards, with no handles.
* **Phone Rows:** Below the `md` breakpoint (767 px and narrower) each row is a three-line card: severity, app and host; the message in two lines; the time and, with AI on, the AI action. Cards are 84 px tall including a 1 px `dark-700` divider (the colour of the toolbar dividers above the list), so where one card ends shows on the dark page. Desktop rows keep their fainter `dark-900` line.
* **Severity Tinting & Badges:**
  * Visual badges reflecting RFC 5424 severity priorities: Emergency / Alert / Critical / Error (Red), Warning (Yellow), Notice / Informational / Debug (Slate / Blue).
* **Navbar Health Figures:** Ingest rate, and on small screens and up queue depth. **Lost: N** (logs LogShed could not queue because its ingestion queue was full; separate from drop rules) appears only when above 0, on every screen size. **UDP lost: N** appears after it only when `udp_receive_errors` is above 0: the syslog UDP messages the kernel discarded because the receive buffer was full. It is separate from Lost, hidden when 0 or unknown, and counts per network namespace (with `network_mode: host` every UDP socket on the host). TCP syslog avoids this loss. The rate's tooltip adds the event loop lag over the last 60 seconds (now, 95th percentile, maximum) when the server reports it, with a line saying what loop lag is, that a healthy LogShed shows a few ms at the 95th percentile, and that at the amber dot's threshold (`LOOP_LAG_WARNING_MS` for `NEAR_LIMIT_DURATION_MS`) LogShed is near its processing limit, so syslog is read late and UDP messages can be lost, in the same words as the dot's tooltip. `docs/SENDING_LOGS.md` ("Reading the Navbar Health Figures") explains every navbar figure for users. The amber dot before the rate shows "Health check degraded or unreachable" when the health check fails; otherwise it shows "LogShed is near its processing limit" once, on every health poll (every 10 seconds) for 30 seconds, `loop_lag_p95_ms` has been at 50 ms or more, or the ingestion queue has held at least 5,000 logs (half of its 10,000) or Lost has grown since the previous poll. The tooltip names the cause (event loop, queue, or both), and the dot clears at the first poll where neither holds. The health and maintenance polls (one each, in the Navbar; the Rules page follows the Navbar's maintenance result) pause while the browser tab is hidden and run at once when it is shown again, as does the 10 second refresh of Incident History. The 5,000 is `QUEUE_WARNING_DEPTH` in `Navbar.tsx`; a backend test keeps it at half of the server's queue size.
* **High-Load Note in the Console:** While the live view runs (no `to` bound), a note sits above the log rows, outside the scrolling list. When the stream sends `skipped` events (the server dropped entries this Console fell behind on), it reads "High load: N live updates skipped. Every log is still stored; search to see them.", adding up the counts, and clears 10 seconds after the last one (`SKIPPED_NOTE_MS`); a new stream (filters changed, reconnect) starts at zero. The search query is matched in the browser, so the server's count includes logs it would hide: with a query set the note adds "(not all of them match your search)" and says "search again". Screen readers get one fixed sentence in a `status` region ("High load: live updates are being skipped. Every log is still stored."), not the count, which changes with every skip. Otherwise, while the Navbar's amber dot is on for the event loop (`loop` or `both`, shared through `utils/nearLimit.ts` so the Console does not poll health itself), it reads "LogShed is busy: live updates may arrive late." A full queue alone does not show it, since the live view is then not late.
* **AI Controls:** AI actions follow the AI setting (`ai_enabled`, or a stored API key when that field is missing; treated as off until settings load). When AI is off, rows and mobile cards have no "Explain with AI" icon (the desktop table drops its Actions column), the selection bar has no "Run Analysis (N)", and the log detail drawer keeps one muted "Explain with AI" entry (tooltip "AI features are turned off in Settings") that opens the AI modal, which explains how to turn AI on.
* **Empty States:** With filters set and no results: "No logs match the current filters." and a "Clear filters" button. With no filters and an empty buffer while the database has logs (for example after Clear buffer): "Waiting for new logs...". With no logs in the database at all (an unfiltered history page with a total of 0, or a facets response with no apps; the facets' hosts do not count, since configured syslog aliases and Docker hosts, including the Primary Docker host, are listed before they log): a first-run card with the syslog listening port inside the container (`syslog_port` from `GET /api/settings`, UDP and TCP; "1514 by default" until settings load) and a note that devices use the host port mapped to it, a copyable `logger` test command with that port, a "Set up Docker hosts" button that opens Settings > Sources, and a pointer to Sending Logs in the documentation.
* **Quick Filters Bar:** Shown on every screen size. On phones it shares the line under the search box with the Filters button, without the "Quick Filters:" label. Pinned saved views come first, as chips with a bookmark icon; a click applies the view as the Views menu does, the chip of the active view (see Saved Views Menu) is highlighted, and a click on the active view clears its filters again. Selected host and app chips share one highlight style. Then up to 6 host chips and 6 app chips, each group after a small "Hosts" or "Apps" label, ranked by how many rows each has in the loaded buffer (ties alphabetical). Hosts are the top level and apps live under them: host chips come from every host and keep their place while any host or app chip is selected, and hosts with no logs for the selected apps stay in place, dimmed and disabled, with a tooltip saying why. App chips follow the selected hosts: with a host selected they are that host's apps (all selected hosts' apps for several), ranked by their volume there; without one they are all apps. Selecting an app never changes the app chips, and a selected app stays visible when a host is then selected. The host ranking is refreshed when no chip is selected, the app ranking when no app is selected, each when the other filters change and at most every 30 seconds while live, so chips do not move as logs stream in. A selected chip stays visible even when it falls out of the top 6. Chips are a fixed height (26 px on phones, 22 px from `md`) with their label trimmed to its letters (`text-trim`, `text-box: trim-both cap alphabetic`), so the text sits in the middle in any font; a monospace font otherwise leaves it about 2 px high. Browsers without `text-box` (before Chrome 133 and Safari 18.2) show it as before.
* **Update badge:** when Settings > Version Updates finds a newer release (and checks are on), an amber badge before Logout links to that release's page (`releases/tag/v<latest>`). From `sm` up it reads "App update available"; below `sm` it shows the icon and the version on one line, and below 360 px the icon alone, so it never wraps or squeezes the Rate figure (which never wraps either). Its name and tooltip always give the full text, and on a phone an invisible layer makes it a 44 px tall tap target without making the header taller.
* **Pull to Refresh (phones):** Pulling down on the navbar or the search and quick filter area reloads the page. The finger must first move 16px, and the gesture counts as a pull only when it moves at least twice as far down as sideways; a sideways swipe (such as scrolling the quick filter chips) never becomes a pull, even if it drifts down later. Touch events bubble through the React tree, so the filter drawer and the dropdown lists inside these areas reach the handlers too: no gesture becomes a pull while any dialog is open, or when it starts in a dialog, a `role="listbox"` or an element marked `data-no-pull-refresh` (the Host and App and Saved Views popovers).
* **Console URL:** `q`, `severity`, `app`, `source`, `time` (start, a relative preset or an absolute time) and `to` (absolute end time, same format as `time`). A link with `time` and `to` opens the Console on that range in custom-time mode, with the live stream paused. `focus=<log id>` is not a filter: once that log is loaded (paging up to 10 older pages of 500 to find it), the Console pauses auto-scroll, scrolls it to the middle of the list and highlights it in amber; the highlight and the parameter are dropped when the filters change.

A click anywhere in a bar's column (the chart's `onClick`, not the drawn bar, so short bars are easy to hit) sets the Console's From to the bar's start and To to a millisecond before its end (To includes its own moment, the next bar's start). In the demo build, the route counts the generated logs in UTC buckets.
  * Checkbox multi-select mode (desktop table, 768px and wider) with a floating action bar: `"Download (N)"`, `"Delete (N)"` and `"Run Analysis (N)"` (only when AI is on).

Up and Down move a cursor from row to row (the first key lands on the first row in view; moving the cursor pauses auto-scroll as scrolling down does, so live rows arriving above it keep the view and the cursor row in place, and a cursor key that scrolls the list to the top, such as Home, leaves it paused), Page Up and Page Down by a screenful less one row, Home and End to the first and last loaded row; the list scrolls to keep the cursor in view, and End near the bottom loads older logs as scrolling does. * **Search & Filter Bar (Query Builder & Facet Bars):**
  * Full-text search supporting SQLite FTS5 query syntax, including the `app:`, `host:`, `source:` and `msg:` prefixes that also filter the live stream. New live rows are filtered with the same `AND`, `OR` and `NOT` grouping as history search (`matchesSearchQuery` in `utils/searchQuery.ts`, following FTS5 precedence, tightest first: words side by side, `NOT`, `AND`, `OR`; brackets group). Terms match the way FTS5 does: the text is split into words like the `unicode61` tokenizer (letters and digits form words, accents are ignored), a term of three or more characters matches at the start of a word (`cron` finds `crontab` but not `acronym`), a shorter term only as a whole word unless it ends in `*` (`io` finds `io` but not `ioctl`; `io*` finds both), a term with punctuation such as `pve-node` or `key=val` is its words in a row with the last one as a prefix, and a quoted phrase is whole words in a row within one field. Each field is split once per row, so matching stays linear in the row's text; a regular expression passed by a caller decides on its own; while the operators are incomplete (for example `error OR` as it is typed), every word must match. Placeholder: `Search logs, e.g. "disk full", error OR timeout, app:nginx`. A `?` button inside the right edge of the search box (left of the clear button) opens a popover with one example each: words (all must match, as prefixes: `time` finds `timeout`), `io*` (a word of one or two letters matches only that word; `*` matches longer ones), `"exact phrase"`, `error OR timeout` and `auth NOT cron` (any case), `app:nginx`, `host:pve-node2` and `msg:"disk full"`. It closes on Esc, an outside click or when focus leaves it.
  * Filters apply as they change; the search icon button next to the box ("Search now", same as Enter) runs the search at once. In the mobile filter drawer, "Done" closes the drawer and runs the search. On phones (below the `md` breakpoint) the search box and the search button have a line of their own. The line below starts with the Filters drawer button, then the match count and Reset while filters are set (Filters and Reset as icons with their count badge), followed by the quick filters and the stream controls, so phones need no separate quick filters band. The search syntax help opens under the box, across its full width on phones.
  * Time selector with presets (Last 15m, 1h, 6h, 24h, 7d and Today, which starts at 00:00 in the server time zone) and a custom date and timestamp picker for bounded historical queries. Presets are saved as relative values, so a saved view keeps meaning "the last hour"; links and saved views carrying `since_midnight` show Today.
  * Multi-select dropdown facet filters for Host Alias (`source_alias`), Source IP, and Container/Application Name (`app_name`). The host and app lists hold at most 500 entries each; when a list was capped, the dropdown (and the mobile filter drawer) shows a note such as "Showing the first 500 hosts. Type a name to add others.", with the number taken from the facets response (`limit`).
  * Numerical severity threshold slider and filter pills (RFC 5424 numerical priorities 0 = Emergency through 7 = Debug).
  * Active filters are marked where they are set, in the toolbar and in the mobile filter drawer: the Host, App, Severity and Time controls get an accent border, accent value text and a clear button ("Clear host / ip filter", "Clear app / container filter", "Clear severity filter", "Clear time filter") that resets that control only, and the search box gets the accent border while it has a query. Time counts as active for any preset but All Time, or a From or To date. The Reset count is the number of active controls, each host and app counting once (`activeFilterControls` in `LogSearchBar.tsx` decides both). The Filters and Reset buttons are named by their text with the count ("Filters 3 active", "Reset 3 active filters"; on the phone toolbar the words are read but not shown), and the Host and App triggers by their label, value and count ("Host / IP: pve-node1 (+1) 2 selected"). In the toolbar and the drawer, as in the form variant, each clear button sits over its trigger as a sibling, never inside the `role="button"` element. Severity and Time (toolbar and drawer) are `SelectDropdown`, a single-choice list in the same box as Host and App (`dropdownStyles.ts`), not native selects: a `button` with `aria-haspopup="listbox"`, named by its label and value ("Severity: Error+ (0-3)"; in the drawer by the label above it), opening a `role="listbox"` that takes focus and marks the active row with `aria-activedescendant`. Enter, Space, Down, Up or Alt+Down open it on the chosen row; Up, Down, Home and End move, a typed letter jumps to the next row starting with it, Enter or Space chooses (a click or tap does too); Esc and Tab close it without choosing and focus returns to the trigger (Tab then moves on). The list opens upwards when there is no room below. Every other single-choice list in the app (the alert rule, preset, test, drop rule, maintenance schedule and AI analysis dialogs, and Settings) is a `SelectDropdown` too, in its `panel` variant: a full-width field named by the visible label above it (`labelledBy`, or a hidden label from its `label` prop where there is none, as for Add Fallback Model). ## 4. Theme & Visual Styling
* **Dark Operations Aesthetic:** Native dark canvas (`color-scheme: dark;` background `#070a10`) tailored for server operations environments.
* **Tailwind CSS 4:** built by the `@tailwindcss/vite` plugin. The theme is the `@theme` block in `frontend/src/index.css` (there is no `tailwind.config.js`), which also fixes the `text-xs` to `text-4xl` line heights to Tailwind 3's rem values, so text given its own size (`text-[11px]`) inside them keeps the parent's line height. Element rules in `index.css` (the page body, input placeholders) sit in `@layer base`, and the log row's default hover in `@layer components`: a plain rule outside any layer beats every utility class, so a row's own `hover:` classes would never show. Placeholders default to Tailwind 3's grey, because Tailwind 4's (half the text colour) falls to about 4.5:1 contrast.
* **Colour roles:** every colour is a role defined once in the `@theme static` block of `frontend/src/index.css`, and Tailwind's stock palette is switched off there (`--color-*: initial`), so a stock class such as `bg-slate-800` or `text-white` produces no CSS at all, with no error from the build or the lint: the element just has no colour. Backgrounds, darkest first: `canvas` (page, wells, inputs), `surface` (cards, dialogs), `surface-hover`, `raised` (controls, chips), `raised-hover`, `raised-strong`, `raised-max`, and `backdrop` behind dialogs. Borders, faintest first: `line-subtle`, `line`, `line-hover`, `line-strong`, `line-stronger`, `line-strongest`. Text, brightest first: `fg-max`, `fg-strong`, `fg`, `fg-soft`, `fg-muted`, `fg-subtle`, `fg-faint`; `on-fill` is text on a filled accent, danger or success button, `on-warning` on a filled warning one. Scales with shades: `accent` (Tailwind's sky; light shades 200 to 400 for text and icons, dark shades 800 to 950, usually with opacity, for tinted backgrounds and borders), `danger`, `warning`, `success`, `info` (notices), `highlight` (AI analysis and digests), `marker` and `neutral` (neutral badges such as severity Info and Debug). Any role works with any colour utility and opacity (`border-danger-800/60`). Code outside class names reads the same CSS variables (`var(--color-accent-500)` in the Storage trend chart, the body and scrollbar colours in `index.css`). A theme is one set of these variables; only the dark theme exists, and a light one would override them under a selector such as `[data-theme=light]`. Add a role or shade there before using it.
* **UI conventions (shared components):** each control is drawn by one component in `components/common/`, so a look is defined once and every screen uses it. Write no new inline button, input, label, checkbox, card or table heading styles; add a variant to the component instead.
  * **Which component to use.** `npm run lint` refuses the elements marked "lint error" in any file under `components/` (except `components/common/`) and in `App.tsx`.

    | For | Use | Never |
    |---|---|---|
    | One choice from a fixed list (mode, severity, provider), or from a provider's list such as AI models | `SelectDropdown`: `variant="panel"` in forms and dialogs, with `labelledBy` and `fieldClassName={SELECT_FIELD_CLASS}`; `variant="toolbar"` in toolbars; `searchable` (panel only) for a long list, with an option's `hint` as a second line | a native `<select>` (lint error) |
    | A host, an app or another name from a list that grows with the logs: searchable, one value or several, with names and patterns typed in | `MultiSelectDropdown`: `variant="form"` in forms and dialogs, with `labelledBy`; `variant="filter"` in toolbars; `singleSelect` when the field stores one value; `allowCustomInput` (on by default) for a name or pattern not in the list | `<input list>`, `<TextField list>` or `<datalist>` (lint errors) |
    | A text, number, password, date or time box; several lines; a checkbox; a label and note around any other control | `TextField`, `TextArea`, `Checkbox`; `Field` around another control | a raw `<input>` or `<textarea>`. The only exceptions are a hidden `type="file"` input opened by a `Button`, and the retention `type="range"` slider |
    | An action | `Button`; `IconButton` for an icon alone; `buttonClass()` for a link or label that must look like a button; `CopyButton` to copy a value | a raw `<button>` with its own classes |
    | A dialog, a side panel, a question before a change that cannot be undone, leaving unsaved edits | `Modal`, `SlideOver`, `ConfirmDialog`, `UnsavedChangesModal`, all on the `useDialog` stack ("Dialogs", below) | a hand-built overlay, or `window.confirm` |
    | A page section, sub-tabs, a table heading, a status or count label | `Card` and `CardHeader`, `Tabs`, `TableHead` (or `TABLE_HEAD_ROW` and `TABLE_HEAD_CELL` on a grid), `Badge` | a box, tab bar, heading or pill styled in place |

    Older screens still hold raw `<button>`, `<input>` and `<textarea>` elements with their own classes, from before these components existed. They are not examples to copy.
  * `SelectDropdown` (`SelectDropdown.tsx`) and `MultiSelectDropdown` (`MultiSelectDropdown.tsx`): a trigger button named by its visible label followed by the value. The panel variant's list is fixed to the viewport, so a dialog's edge never cuts it off. A `SelectDropdown` option may carry a `hint`, a second muted line under its label in the list (not on the trigger). With `searchable` (panel variant; every AI model picker: Settings' Default Primary Model and Add Fallback Model, and the AI analysis dialog's Primary Model and Add Fallback Model, for every provider) the list opens under a search box (`role="combobox"`, named "Search <label>", controlling the listbox) that takes focus, empty; rows whose label or hint holds every typed word, in any order and case, stay, and `pinned` options ("Custom model name...", "-- Add Fallback Model --") always do. After each change to the text the first row that is not pinned is active (the first pinned one when only pinned rows are left), so Enter chooses the first match. A press on the popup around the box and the list (its padding, the no-match note) keeps focus in the box; the list itself, scrollbar included, takes presses as before. Up and Down move over the rows shown, Page Up and Page Down jump to the first and last, and Enter chooses; Space, Home, End and letters edit the text; with no row at all (a list without pinned rows) it says `Nothing matches "<text>".` and Enter chooses nothing and leaves it open. Without a search box, Enter on an empty list closes it. Esc and Tab close it as before. Model rows give OpenRouter's price and context size as their hint ("$0.75 in / $3.75 out per 1M tokens, 1.05M context", "Free", and "being retired" for a model with an end date; `aiModelHint` in `utils/aiPrompt.ts`). With OpenAI-Compatible chosen and a base URL on `openrouter.ai` (`isOpenRouterUrl`), Settings shows a note under the base URL that OpenRouter is now a provider of its own. `MultiSelectDropdown`'s `form` variant has the text box look (34 px, `bg-canvas`, 4 px corners) and shows the chosen names in monospace; with `singleSelect`, picking or adding a value replaces the choice and closes the list, and there is no Select All. Typing a listed name (in any case) and pressing Enter picks the listed one; with `allowCustomInput`, other text is added as typed.
  * `Button` (`Button.tsx`): variants `primary` (the main action, white on `accent-700`), `secondary` (other actions and Cancel), `danger` (deletes and revokes), `danger-soft` (a red-tinted secondary action, such as Discard Changes), `soft` (an accent-tinted action beside content, such as installing a preset) and `ghost` (a quiet toolbar or row action); sizes `sm` (at least 32 px tall below `md`), `md` (default) and `lg`; 4 px corners (`rounded-sm`) and a 1 px border on every variant, so buttons side by side are the same height; `type="button"` unless given. `IconButton` is an icon-only button that always has a name (`label`, also its tooltip), at least 32 px square below `md`. `DisclosureButton` is a left-aligned row with a chevron that opens and closes the part under it (`open`, `onToggle`, `aria-expanded`), as in the log drawer's JSON tree. `buttonClass()` gives a link the same look.
  * `Field`, `TextField`, `TextArea`, `Checkbox` (`Field.tsx`): a plain label above the control (`text-xs`, medium weight, `fg-soft`), a hint or an error under it, with `htmlFor`, `aria-describedby` and `aria-invalid` wired; `Field` hands its ids to any other control (a `SelectDropdown` takes `labelledBy` and `fieldClassName={SELECT_FIELD_CLASS}`, so it matches the text boxes). Text boxes are `bg-canvas`, 4 px corners, `text-xs` on every screen (the zoom on focus is handled by the viewport, below), `mono` for addresses, patterns and URLs. A checkbox is the browser's own control ticked in `accent-600` (`accent-color`).
  * `Card` and `CardHeader` (`Card.tsx`): the raised box of a page section (`padded`, or `flush` for a list or table that runs to its edges), and its heading: a small upper-case title after an accent icon, a description, and actions at the right (under the title on a phone).
  * `Tabs` (`Tabs.tsx`): a page's sub-tab bar, a navigation landmark named by `label`, with the shown tab marked `aria-current="page"`.
  * `TableHead` and `TABLE_HEAD_ROW`/`TABLE_HEAD_CELL` (`Table.tsx`): one heading style for every table and table-like grid, small upper-case sans text with letter spacing on a slightly darker strip; monospace only in data cells that hold addresses, IDs or URLs.
  * `Badge` (`Badge.tsx`): a small status or count label in a tone (`neutral`, `accent`, `success`, `warning`, `danger`); not a control.
  * `ConfirmDialog` (a question with Cancel and a `danger` confirm, or `confirmVariant="primary"`), `UnsavedChangesModal`, `Modal`, `SlideOver` and `CopyButton` (`ghost`; `link` beside a command; `button`, a secondary Button beside a read-only field; `compact` in a code block's header; `icon`, the icon alone with its label for screen readers and as its tooltip, beside each value in a list) use the components above. A `Button` keeps its label on one line unless given `wrap` (a `whitespace-normal` added through `className` would lose to the look's `whitespace-nowrap`, because Tailwind orders utilities by stylesheet, not by class order).
* **Typography:** sans-serif (`Inter`, then system-ui; `--font-sans` in `index.css`) for the interface, monospace (`--font-mono`, `font-mono`) for what is read or typed exactly. Most text is `text-xs`; larger sizes are for headings and the `lg` button. Colours are text roles from "Colour roles" above.
  * Page: one `<h1>` per page ("Accessibility Baseline", below). The Rules, Storage and Settings pages head their content with a visible `h2`, `text-base font-bold text-fg-strong`, after an icon.
  * Section: `CardHeader`'s title, an `h3` unless `as` says otherwise (`SECTION_TITLE_CLASS`: `text-xs font-semibold uppercase tracking-wider text-fg-soft`), with its description in `text-xs text-fg-muted`. A list heading inside a card reuses `SECTION_TITLE_CLASS`; a smaller sub-heading is `text-xs font-semibold text-fg-soft`.
  * Dialog: the title is the `h2` drawn by `Modal` or `SlideOver` (`text-sm font-semibold text-fg tracking-wide`), and headings inside start at `h3`.
  * Table heading: `TABLE_HEAD_ROW`, `text-[11px] font-semibold uppercase tracking-wider text-fg-muted`.
  * Field label: `LABEL_CLASS` (`block text-xs font-medium text-fg-soft`, `mb-1`), drawn by `Field`, `TextField` and `TextArea`. A dropdown's label is a `<span>` or `<label>` with `LABEL_CLASS` and an `id` its `labelledBy` names, or `LABEL_TEXT_CLASS` (the same without the margin) when the label sits in a `space-y-*` stack or shares a row with links or a button. `REQUIRED_MARK` follows the text of a field that must be filled in.
  * Helper text: `text-[11px] text-fg-muted` under a control (`Field`'s `hint`), `text-[11px] text-danger-400` for an error (`Field`'s `error`). `Badge` text is `text-[10px]`.
  * Monospace: `mono` on a text box that holds an address, a pattern, a URL or a command; table cells that hold addresses, IDs or URLs; log lines and timestamps; code blocks. Labels, headings, notices and help text stay sans-serif, even when they name a host or an app; the name alone may be a monospace `<span>`.
* **Layout & spacing:**
  * A component's `className` is for layout only (width, margins, flex and grid placement), never colour, padding, font or corners, which belong to its variants.
  * A vertical stack uses `space-y-*`: `space-y-4` between a form's fields (`space-y-6` between the sections of a long form, such as Settings), `space-y-1` between a label and its control. `space-y-*` puts its margin below each child except the last, which an inline element ignores: give a `<label>` or `<span>` inside one `block`.
  * Things side by side use `flex` or `grid` with `gap-*` (`gap-2` in a row of buttons or chips, `gap-1.5` between an icon and its text), never `space-x-*`: a child hidden at some widths would keep a stray margin. Fields side by side are `grid grid-cols-1 sm:grid-cols-2 gap-3` (or `sm:grid-cols-3`), one column on a phone.
  * Breakpoints are Tailwind's own. `sm` (640 px) puts fields side by side and a `CardHeader`'s actions beside its title. `md` (768 px) is where tables turn into cards on narrower screens, and below it (`max-md:`) small buttons and icon buttons are at least 32 px for touch. `lg` is used only for a few wide layouts.
* **Layout Stability:** Built-in `scrollbar-gutter: stable` and slim scrollbars (`::-webkit-scrollbar`) to eliminate layout shifts when virtual lists update.
* **Accessibility Baseline:** Every page passes the axe rules run by the UI check at 375, 640, 767 and 1280 px. The viewport allows pinch zoom: it has no `maximum-scale`, except on iPhones and iPads, where `utils/iosViewport.ts` (run from `main.tsx`) adds `maximum-scale=1` at start-up. That stops iOS Safari zooming the page when a text field under 16 px gets focus, and iOS ignores `maximum-scale` for pinch zoom (since iOS 10), so pinch zoom still works there. Android honours `maximum-scale`, so it keeps the plain viewport; it does not zoom on focus. An iPad that reports itself as a Mac is told apart by its touch points. The maintenance end time field stacks above its button on phones. Each page has one `<h1>` (visually hidden on the logged-in pages, named after the navbar entry) inside a `<main>` landmark, including login and first-run setup. White text sits on `bg-accent-700` (`#0369a1`, 5.9:1), with `hover:bg-accent-600`; `accent-600` behind white text gives only 4.1:1. Form controls have a label (`<label htmlFor>` for text fields, through `Field` and `TextField`, the label and value for every `SelectDropdown`, `aria-label` for the retention slider), a control's name contains its visible text, the Console log list has the keyboard row cursor above, and scrolling code examples (the maintenance cURL commands) are focusable regions. The UI check also covers Incident History, an open incident and Maintenance, and `.scripts/ui-check/keyboard.mjs` (maintainer tooling) checks the row cursor and dialog focus with the keyboard only, including each drawer action's dialog on top of the drawer.
* **Dialogs:** `Modal` (which the API token dialogs also use; `closeOnEscape={false}` keeps the one-time token dialog open on Esc) and `SlideOver` are `role="dialog"` with `aria-modal="true"`, named by their title (an `h2`, `aria-labelledby`; headings inside a dialog start at `h3`). `useDialog` in `utils/dialogStack.ts` keeps one stack of open dialogs with one keydown listener: Esc closes only the top dialog, Tab and Shift+Tab wrap inside it, opening moves focus in (an `autoFocus` field keeps it, else the first `data-autofocus` element, else the dialog itself), and closing returns focus to the element that opened it, or, when that element has gone with a dialog this one replaced (the deleted Docker host notice hands over to the Docker host or alias dialog), to that dialog's opener. Dropdowns and menus that handle Esc themselves (`MultiSelectDropdown`, `SelectDropdown`, `SavedViewsMenu`) take it in the capture phase and stop it, so they close before the dialog around them; while one of the Saved Views menu's own dialogs is open, that dialog takes Esc. The one-time API token dialog ignores Esc, because the token cannot be shown again. While any dialog is open, the page's `overscroll-behavior` is `none` (on `html` and `body`, restored when the last one closes), so a swipe on a backdrop or a short dialog cannot start a phone browser's own pull-to-refresh either. A question before a delete or another change that cannot be undone is a `ConfirmDialog` (a `Modal` with Cancel and a confirm button), and leaving unsaved edits asks through `UnsavedChangesModal` (Keep Editing, Discard, and Save & Continue where the edits can be saved from there).

## 5. Build & Asset Distribution
* **Vite Bundling:** Vite compiles production static assets directly into `backend/app/static/`, for Vite's default browser target (Baseline Widely Available: Chrome and Edge 111, Firefox 114, Safari 16.4); Tailwind CSS 4 raises Firefox to 128. After the build, a plugin in `frontend/vite.config.ts` writes a Brotli (`.br`, quality 11) and a gzip (`.gz`, level 9) copy next to each `.js`, `.mjs`, `.css`, `.html`, `.svg` and `.json` file of at least 512 bytes, the copied `/docs-assets/` included, keeping each copy only when it is at least 10% smaller. It uses Node.js's built-in `zlib`.
* **FastAPI Static Serving:** `backend/app/core/static_files.py` serves the build: `/assets/` from a `StaticFiles` mount, other files by path, and `index.html` for every other path (SPA fallback; `/api` and `/mcp` paths return `404`). When a `.br` or `.gz` copy exists and the request's `Accept-Encoding` allows it (q above 0; Brotli first), that copy is sent with `Content-Encoding` and the original file's content type, and every response for such a file carries `Vary: Accept-Encoding`. Each copy has its own `ETag`, and `If-None-Match` or `If-Modified-Since` get `304`. Content-hashed files under `/assets/` are sent with `Cache-Control: public, max-age=31536000, immutable`; `index.html` and every other unhashed file with `no-cache`, so a new release loads at once. Nothing is compressed at request time, so API responses and the SSE streams are never compressed or buffered.
