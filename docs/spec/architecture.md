# Specification: System Architecture & Process Model

> Modular specification extracted from [docs/SPEC.md](../../docs/SPEC.md).

## 1. System Architecture & Process Model
Single Docker container running Python 3.14 (`asyncio`) + FastAPI backend serving a pre-built React SPA, with background ingestion workers managed under isolated supervisors.

- **Process Boundaries:** Main thread runs `uvicorn` and supervised background tasks (`SyslogServer`, `DockerCollectorPool`, `QueueConsumer`, `FTSIndexWorker`, `PruneWorker`, `StorageMetricsWorker`, `ModelRefreshWorker`, `DropFilterWorker`, `MaintenanceSweepWorker`, `DailyDigestWorker`, and `LoopLagMonitor`). SQLite operations must use stdlib `sqlite3` and offload synchronous queries via `asyncio.to_thread()` (per AGENTS.md, `aiosqlite` is not used). Thread-local connection reuse (`get_thread_connection` in [`backend/app/api/deps.py`](../../backend/app/api/deps.py)) eliminates connection setup overhead across queries in worker threads with defensive rollback guards in `finally` blocks preventing WAL lock leaks. Lifespan shutdown coordinates termination across background supervisors and active Model Context Protocol (MCP) client sessions (`stop_mcp_session_manager`).
- **Console Logging:** `install_console_log_handler()` in [`backend/app/main.py`](../../backend/app/main.py) adds one `StreamHandler` to the `app` logger when `app.main` is imported (found again by a marker attribute, so repeated imports and `create_app.uncached()` add no second one). It writes `INFO` and above to the current `sys.stderr` as `YYYY-MM-DD HH:MM:SS LEVEL logger.name: message`, with the time in the server's time zone (`get_server_tzinfo`). The `app` logger stays at `INFO` (or `DEBUG` when the internal log level is `DEBUG`) and keeps propagating, and the root logger has no handler, so nothing prints twice and pytest's `caplog` sees every record. `InternalLogHandler` filters by its own level, so what is stored does not change. Loggers outside `app` (uvicorn, `httpx`) print through their own configuration.
- **Supervised Background Workers:** The application maintains supervised background tasks isolated by supervisor wrappers (`_supervise_worker` and `_supervise_tailer`) that catch exceptions, log diagnostics, and restart failing tasks with exponential backoff without disrupting the event loop:
  1. `SyslogServer`: Asynchronous UDP and TCP syslog listener on port 1514 (supporting RFC 3164, RFC 5424, and RFC 6587 framing).
  2. `DockerCollectorPool`: Supervises multiple concurrent `DockerTailer` workers streaming container logs across local Unix sockets, remote TCP proxies, and mutual TLS endpoints.
  3. `QueueConsumer`: Drains the in-memory buffer queue, applies active drop rules, evaluates alert rules, persists batch chunks to SQLite, broadcasts live SSE events, and signals the FTS indexing worker.
  4. `FTSIndexWorker`: Asynchronously batches unindexed log entries into the `logs_fts` external content table with durable state tracking.
  5. `PruneWorker`: Runs automated daily retention purging of logs, alert history and linked AI audit records coordinated with the FTS watermark, followed by index compaction and WAL truncation.
  6. `StorageMetricsWorker`: Samples database file footprint and host mount disk metrics hourly and immediately following pruning operations.
  7. `ModelRefreshWorker`: Discovers and caches available AI models from the configured provider every 12 hours.
  8. `DropFilterWorker`: Flushes in-memory drop rule match counts to SQLite every 30 seconds to prevent database write contention.
  9. `DailyDigestWorker`: Compiles and delivers scheduled 24-hour analytical rollup digest notifications across configured channels. This worker performs deterministic SQL metric aggregations (ingestion volume, error counts by entity, noisy services, storage footprint delta) and operates independently without AI models or prompt synthesis. The worker checks every 30 seconds and sends once per local day (container `TZ`) when the digest is on, the schedule time (`daily_digest_schedule_time`, default `09:00`) has passed and `daily_digest_last_run` is on an earlier day. A digest missed while the container was down is sent when it starts again that day. When the digest is turned on or its schedule time changes, `POST /api/settings` stores the moment in `daily_digest_armed_at`, and the first digest is the next occurrence of the schedule time after it (tomorrow if today's time has passed), so saving the schedule never sends a digest at once. A save that repeats the stored values does not change `daily_digest_armed_at`, and a missing or unreadable value puts no limit on the run (installs upgraded from 1.2.x). `POST /api/notifications/digest/send` sends at once, sets `daily_digest_last_run` (which skips that day's scheduled digest) and does not touch `daily_digest_armed_at`.
  10. `MaintenanceSweepWorker`: Every 30 seconds, closes maintenance sessions that passed their planned end as `expired`, flushes the in-memory per-session dropped-log counts to SQLite, and refreshes the in-memory cache of active sessions. It runs once at startup so `drop_errors` sessions keep working after a restart.
  11. `LoopLagMonitor`: Sleeps 100 ms in a loop and records how late each wake-up is, keeping the last 60 seconds in memory. `GET /api/health` and `GET /api/v1/system/metrics` report the latest, 95th percentile and maximum lag, which show how close the single event loop is to its processing limit.
- **Start-up States** ([`backend/app/core/lifecycle.py`](../../backend/app/core/lifecycle.py)): before migrating, the lifespan reads `user_version` and `/data/.migration_failed` without changing the database (`start_up_plan`).
  - **Fast path** (new database, current schema, or a schema newer than the app): migrate, start the services above, then `yield`, as before; the status stays `ready`, so `TestClient` tests are unaffected. A newer schema still stops start-up (`DatabaseNewerThanAppError`).
  - **Upgrade path** (`0 < user_version < latest`): reads the encryption key, sets `upgrading` and `yield`s at once, so uvicorn binds the port; a background task runs `run_migrations` (backup, then steps, reporting `stage`, `done` and `total`), then starts the services and sets `ready` (if starting them raises, LogShed logs it and sends itself `SIGTERM`, as a failure at a normal start would stop it). Until then `LifecycleMiddleware` answers a browser `GET` outside `/api` and `/mcp` with a self-contained status page (`503`, inline style only, `<meta http-equiv="refresh" content="3">`, no script) and every other request except `GET /api/health` with `503` and `Retry-After: 5`, all `Cache-Control: no-store`. No listener runs, so no logs are received.
  - **Recovery** (the backup could not be made, a step failed, or a marker from this version names a schema not reached): `.migration_failed` is written (`app_version`, `from_schema`, `target_schema`, `current_schema`, `failed_at`, `stage` `backup` or `migration`, `backup_filename`, `error` cut to 2,000 characters), one notification goes to every enabled channel (only when the marker is written, not on a restart into recovery), and the status is `recovery`. The middleware lets through the web UI's static files, `GET /api/health`, `GET /api/auth/status`, `POST /api/auth/login` and `logout`, `GET /api/system/recovery`, its `POST .../retry` and `.../skip-backup`, and `GET /api/system/backups/{filename}/download`; everything else gets `503`. Retry and skip-backup claim the state under a lock (a second click gets `409`), remove the marker and run the upgrade path again (the lifespan keeps every upgrade task and waits for all of them at shutdown); Retry passes `backup=False` when the marker's archive still exists and `user_version` still equals its `from_schema`.
  - A marker is removed at start-up when its `app_version` differs from this one or `user_version >= target_schema`.
  - The state lives in the module, never on `app.state` (the cached test app is shared). At shutdown the lifespan sets a cancel event: a running backup stops at its next 4 MiB chunk (or its `VACUUM INTO` through a progress handler) and deletes its files, no further step starts, and nothing is written to the marker; the lifespan then waits for the task and stops the services. The web UI's "Create backup now" job is stopped the same way.
- **Failure Isolation:** Worker exceptions must be caught, logged, and restarted with exponential backoff without crashing the event loop.
- **Security & Privileges:** Container starts as root to allow [`entrypoint.sh`](../../entrypoint.sh) to configure permissions. It reads `PUID` and `PGID` environment variables (defaulting to 1000:1000; the entrypoint prints an error naming the variable and exits with status 1 before changing anything when either is `0`, so LogShed never runs as root), maps the `appuser` to match, dynamically detects the Docker socket GID and adds the user to that group (for a socket owned by group `0` that is the root group, as in 1.2.x, and a warning recommends a Docker socket proxy), changes ownership of `/data`, and drops privileges via `gosu appuser`.
- **Docker Endpoints:** Primary daemon connects via `DOCKER_HOST` (`unix:///var/run/docker.sock` or `tcp://proxy:2375` for `tecnativa/docker-socket-proxy`). Additional remote Docker hosts can be pre-seeded via `DOCKER_ADDITIONAL_HOSTS` and managed dynamically through the Web UI and REST API.

### 1.1 Configuration Architecture: Bootstrap Primitives vs. Runtime Settings
LogShed separates configuration into **bootstrap primitives** (required before the SQLite database unlocks or privilege reduction occurs) and **runtime settings** (configurable through the Web UI and persisted in `system_settings`).

#### Bootstrap Primitives (Container Environment Only)
The following environment variables are supplied at container start and are strictly container-level primitives:
- `PUID` and `PGID` - User and group IDs for the application to run as via `gosu` privilege reduction (defaults to `1000:1000`).
- `TZ` - Container runtime timezone (defaults to `UTC`). Resolved at runtime and exposed through `/api/settings` to align UI presentation and AI timeline analysis with the homelab host or container clock. `server_timezone` is always an IANA zone name (a leading `:` in `TZ` is dropped), or `null` when the server zone has none (an unknown `TZ`, or `TZ` unset with a non-UTC `/etc/localtime`); the UI then shows browser time. It is never an abbreviation such as `BST`, which browsers can read as a different zone.
- `PORT` - Web/API HTTP port (defaults to `8080`).
- `SYSLOG_PORT` - Syslog listening port for UDP and TCP (defaults to `1514`).
- `DATA_DIR` - Mount path for persistent SQLite database, master key, and presets (defaults to `/data`).
- `LOGSHED_SECRET_KEY` - Optional master key (a 32-byte URL-safe base64 key, or a passphrase, which goes through scrypt) from which the session and stored-secrets keys are derived; if unset, auto-generated at `/data/.secret_key`.
- `DOCKER_HOST` - Docker endpoint socket or proxy address (defaults to `unix:///var/run/docker.sock`).
- `DOCKER_ADDITIONAL_HOSTS` - JSON array of remote Docker host endpoints to pre-seed on container boot.
- `MAX_RETENTION_DAYS` - Ceiling in days for the log retention slider in the UI (defaults to `30`, minimum `1`). While it is set it is also saved as the retention at startup and the slider is fixed to it; removing it keeps the saved value.
- `AUTO_BACKUP_ON_MIGRATION` - Back up the database before a schema upgrade (default on; `false` turns it off). When set it wins over the stored `backup_before_migration` setting (the Storage page's checkbox), which the UI then shows locked. See the database backups section in [database.md](database.md).
- `ENVIRONMENT` / `DEBUG` - `ENVIRONMENT=development` adds the localhost development CORS origins and debug logging (`production` by default). `DEBUG=true` alone no longer trusts localhost origins.
- `CORS_ORIGINS` - Comma-separated list of allowed cross-origin hosts (defaults to empty in production). A `*` entry is ignored and logged as an error.
- `ENABLE_API_DOCS` - Serves `/docs`, `/redoc` and `/openapi.json` (default `true`).
- `DOCKER_ALLOWED_SOCKETS` - Comma-separated extra Unix socket paths accepted for Docker hosts whose path does not end in `docker.sock`.
- `INGEST_MAX_BODY_BYTES` - Largest `POST /api/v1/ingest` body in bytes (default 5 MiB).
- `USER_REGEX_TIMEOUT_MS` - Per-match time limit for user alert and drop rule patterns (default `50`).
- `MCP_ALLOW_QUERY_TOKEN` - Accepts MCP API tokens in the URL query string (default `false`; a supported opt-in for MCP clients that cannot send headers).
- `SYSLOG_MAX_TCP_CONNECTIONS_PER_IP` - Concurrent Syslog TCP connections allowed from one source IP (default `20`; environment only, not a runtime setting).
- `SQLITE_TMPDIR` - Folder for SQLite's temporary files (`VACUUM`'s copy of the database, sorts that spill). The image sets `/data/.tmp`; `entrypoint.sh` moves it beside the database when `DB_PATH` or `DATA_DIR` change, then creates it (owned by the app user, mode `0700`). A different value set by the user is left as it is. SQLite reads it once when the process starts, so it must be in the environment, not set from Python; `docker exec` commands get the image's value.
- `SYSLOG_UDP_RECEIVE_BUFFER_BYTES` - Receive buffer requested for the UDP syslog socket, in bytes (default 8 MiB, `0` keeps the OS default; environment only). The kernel caps it at `net.core.rmem_max`.

*Storage Compatibility Note:* `DB_PATH` and `SECRET_KEY_PATH` remain supported as backward-compatible path overrides.

#### Three-Tier Resolution Hierarchy
Runtime operational settings follow a resilient three-tier resolution hierarchy:
1. **Tier 1 (Highest Priority):** Value persisted in SQLite (`system_settings` table) via Web UI.
2. **Tier 2 (Fallback):** Environment variable set on container (including silent legacy aliases).
3. **Tier 3 (Default):** Built-in hardcoded constant.

Settings updates apply dynamically to in-memory workers (`SyslogServer`, `DockerCollectorPool` (which manages `DockerTailer` tasks per host), `AlertEvaluator`, `NotifierService`, `Auth`, and `MCP`) without requiring container recreation. An in-memory thread-safe cache (`get_cached_system_settings` with 10-second TTL fallback) ensures high-throughput request evaluation without redundant SQLite I/O.

The runtime operational and advanced settings are:
- `enable_mcp`: Master toggle for the embedded Model Context Protocol (MCP) server (Env: `LOGSHED_ENABLE_MCP`, default: `False`). Managed via the API & MCP Access tab.
- `ai_timeout`: Outbound AI request timeout in seconds (Env: `LOGSHED_AI_TIMEOUT`, default: `45.0`).
- `ai_thinking_level`: How much reasoning models think: `off` (or the lowest level where a model keeps thinking), `low`, `medium` or `high` (Env: `LOGSHED_AI_THINKING_LEVEL`, default: `low`; `LOGSHED_AI_THINKING_BUDGET` is still read as its level). It replaced the token budget `ai_thinking_budget` in 1.3.0; see `ai-engine.md` section 4 for the mapping per provider.
- `app_url`: Public base instance URL for action links in push notifications (alert notifications link to `<app_url>/rules/history?id=<history id>`, which opens that incident) (Env: `APP_URL`, legacy alias: `app_url`, default: `""`).
- `allow_private_notification_targets`: Permit notification webhooks to target LAN/RFC1918 IPs and `.local`/`.internal`/`.lan` hosts (Env: `ALLOW_PRIVATE_NOTIFICATION_TARGETS`, default: `True`).
- `enable_docker`: Switch for the local Docker host (endpoint 1, "Primary Docker"), kept in step with that endpoint's `enabled` flag (Env: `ENABLE_DOCKER`, default: `True`; `false` in the environment keeps endpoint 1 off whatever is stored). It does not affect other Docker hosts, which each follow their own `enabled` flag.
- `docker_exclude_containers`: Comma-separated container names/IDs to ignore (Env: `DOCKER_EXCLUDE_CONTAINERS`, default: `""`).
- `docker_source_alias`: Source attribution alias for Docker logs (Env: `DOCKER_SOURCE_ALIAS`, default: `"docker"`).
- `trusted_proxies`: Comma-separated proxy IPs or CIDR blocks for client IP resolution (Env: `TRUSTED_PROXIES`, default: `""`); loopback is a proxy only when listed. Recommended over `trust_docker_proxies`.
- `trust_docker_proxies`: Trusts every address in `172.16.0.0/12` to set `X-Forwarded-For` (Env: `TRUST_DOCKER_PROXIES`, legacy aliases: `TRUST_DOCKER_NETWORKS`, `TRUST_DOCKER_GATEWAY`, default: `False`). If clients can reach LogShed through the Docker userland proxy or hairpin NAT, they appear as the bridge gateway and can spoof their address to avoid the per-address login limit. Prefer `TRUSTED_PROXIES=<reverse proxy container IP>`. LogShed logs a warning at startup while this option is in effect.
- `cookie_secure`: Force `Secure` flag on session cookies behind SSL proxies stripping `X-Forwarded-Proto` (Env: `COOKIE_SECURE`, default: `False`).
- `syslog_max_tcp_connections`: Maximum concurrent Syslog TCP connections (Env: `SYSLOG_MAX_TCP_CONNECTIONS`, default: `250`).
- `syslog_tcp_inactivity_timeout`: Syslog TCP client inactivity timeout in seconds (Env: `SYSLOG_TCP_INACTIVITY_TIMEOUT`, default: `0.0` - disabled).

Sensitive configuration - AI provider, AI API key (Fernet-encrypted), AI base URL, AI model, AI fallback models, custom system prompt, internal log level, version update check toggle, and active retention days - is managed through the primary Application Settings tab.
