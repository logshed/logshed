# Changelog

All notable changes to LogShed will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.3.0] - Unreleased

### Upgrade Notes

Read these before updating from 1.2.x. The first start migrates the database to schema version 3 (new tables and columns for API tokens, Docker hosts, AI follow-up threads and rule order), so back up `/data` first if you may want to return to 1.2.x.

- **`PUID` or `PGID` set to `0` will stop working in a later release.** Starting with a later release, LogShed will refuse to start when `PUID` or `PGID` is set to `0`. In 1.3.0 it still starts and logs a warning at startup. Set `PUID` and `PGID` to a non-root user (for example 1000) now.
- **The API docs need a login.** `/docs`, `/redoc` and `/openapi.json` were public in 1.2.x. They now need the web login: without a session, `/docs` and `/redoc` redirect to the login page and `/openapi.json` returns `401`. A script that fetched `/openapi.json` anonymously must send a valid API token in `Authorization: Bearer` (any scope works). `ENABLE_API_DOCS=false` turns the pages off. Swagger UI and ReDoc are now served by LogShed itself, so they also work without internet access.
- **Log timestamps up to 5 minutes ahead are kept.** Syslog and Docker timestamps more than 60 seconds ahead of the received time used to be replaced. The window is now 5 minutes for every source, so a device whose clock is a few minutes fast keeps its own timestamps.
- **Very long multiline entries are stored as several entries.** A merged entry (such as a long stack trace) is split at 64 KB instead of growing to about 256 KB. No lines are lost.
- **UDP receive buffer.** LogShed now asks for an 8 MiB receive buffer on the UDP syslog socket (`SYSLOG_UDP_RECEIVE_BUFFER_BYTES`; `0` keeps the OS default). On a default Linux host (`net.core.rmem_max` of 212992) the kernel grants less, and every start logs a warning that names the size it got. Run `sysctl -w net.core.rmem_max=8388608` on the Docker host (add it to `/etc/sysctl.conf` to keep it; a Compose `sysctls:` entry cannot set it), or set `SYSLOG_UDP_RECEIVE_BUFFER_BYTES` to the size in the log message to silence the warning. See [UDP or TCP syslog](docs/SENDING_LOGS.md#udp-or-tcp-syslog).
- **Shutdown can take up to 2 seconds longer** right after a TCP syslog sender disconnects, while LogShed stores the messages it had already received.
- **Alert rule patterns with backslash codes now match.** A pattern containing `\` (such as `\bKilled`, `error \d+` or `foo\.bar`) is now a regular expression, so rules that never fired because the backslash was compared as text start to fire. To match a literal backslash, write `\\`: `C:\temp` now means "C:", a tab and "emp". A stored pattern that is not a valid regular expression (such as `C:\Temp`) keeps matching as plain text and logs a warning each time the rules load; a new rule with such a pattern is refused when you save it. See the [Rules Guide](docs/RULES_GUIDE.md).
- **Slow rule patterns are switched off automatically.** An alert or drop rule whose pattern times out 20 times within 5 minutes (the limit is 50 ms per match, `USER_REGEX_TIMEOUT_MS`) is saved as disabled, and an error naming the rule is logged. Simplify the pattern, then enable the rule again.
- **Stricter rule patterns and two new packages.** User-written alert and drop rule patterns now run on the `regex` package with a real per-match time limit. Saving or importing a rule refuses more patterns that are prone to catastrophic backtracking, such as `(a|a)+` or `(.*a){20}`; importing an older export that holds one fails for that rule, and rules that are already saved keep running under the time limit. LogShed also needs the `mcp` package. The image includes both; source installs must run `pip install -r backend/requirements.txt` again.
- **CORS and debug mode.** `CORS_ORIGINS=*` is now ignored and an error is logged, because with credentials it let any website send logged-in requests; list each trusted origin. `DEBUG=true` no longer trusts localhost development origins; use `ENVIRONMENT=development`. Cross-origin requests may send only the `Content-Type`, `X-Requested-With` and `Authorization` headers.
- **Content-Security-Policy.** Every page now sends a strict policy, so scripts that a reverse proxy injects into LogShed pages are blocked by the browser.
- **File permissions.** New database files are created with `umask 027`, so other users on the host cannot read them. A host backup tool running as a different user may lose read access to files created after the upgrade.
- **Syslog limits.** One source address can hold at most 20 TCP connections (`SYSLOG_MAX_TCP_CONNECTIONS_PER_IP`); extra connections are refused with a warning. Syslog messages over 65,536 characters are cut and end with a `[truncated]` marker.
- **The redactor removes more.** AI prompts and API output now hide the user name in any `scheme://user@host` URL (for example `ssh://git@github.com`), the rest of the line after `Cookie:`, and text after a lone `-----BEGIN ... PRIVATE KEY-----` up to the next punctuation. Lines over 16 KB in redacted output are cut with a `...[truncated]` marker.
- **`DOCKER_HOST` addresses.** A `DOCKER_HOST` that is, or resolves to, a link-local or cloud metadata address (for example `169.254.169.254`) is now refused when LogShed connects.
- **Drop preset fix does not update rules installed earlier.** The "Systemd Session Chatter" preset now matches only PAM systemd-user "session opened" and "session closed" lines. Rules you installed from the old preset keep the old pattern, which never matched; reinstall the preset or edit the rule.
- **Anonymous version check.** `/api/system/version` no longer shows the running version to anonymous callers.

### Added
- **External REST API (`/api/v1/*`)**: Programmatic API for automated log queries, aggregation facets, incident history, maintenance window control, system metrics, version and update status, and storage compaction. `GET /api/v1/logs` pages with an opaque `cursor` (`next_cursor` is `null` on the last page, malformed cursors return `422`), so deep pages stay cheap and stable while new logs arrive; `total` counts every row matching the filters (capped at 1001, with `total_capped`). Log context for logs without a source alias or app name matches correctly and returns `404` for an unknown log ID. Searches with punctuation such as `foo-bar`, `key=value` or `user@host` fall back to plain token search like the web UI, searches wake the full-text indexer so the newest logs are included, and a locked database returns `503` "database is busy". `GET /api/v1/system/version` (`system:read`) returns the installed version and the latest stable release from the cached update check, so tools such as Home Assistant can show available updates; it cannot force a registry request. `GET /api/v1/system/metrics` shares one refresh between concurrent callers, reports 24-hour log counts per severity from emergency to warning (`severity_counts_24h`) next to the combined `error_count_24h` and `error_count_1h`, and its `alert_state` counts only alert rule firings (daily digests, on-demand analyses and maintenance windows are left out). Prune and vacuum (`POST /api/v1/system/prune`, `/vacuum`) share the web UI's in-progress lock (`409` while one runs) and have a 5-minute cooldown that starts only after a successful run. Log text, alert samples and AI diagnosis text in responses pass through the secret redactor (best-effort). Filters accept at most 50 `source` or `app_name` values (`422` beyond).
- **Bearer Token Authentication & Granular Access Scopes**: Bearer tokens (`ls_live_<40 hex>`) with SHA-256 hash storage, scoped permissions (`logs:read`, `logs:write`, `alerts:read`, `system:read`, `system:write`, `maintenance:read`, `maintenance:write`, namespace wildcards such as `maintenance:*`, and full access `*`; unknown scopes are rejected and a token holds at most 20), sliding-window rate limiting (120 requests per minute), last-used tracking, and a management UI under Settings > API & MCP Access. The `Bearer` scheme name is accepted in any letter case. Every token path (REST, ingestion, MCP) shares one verifier, and revoking a token immediately clears its rate limit window and cached ingestion entry. The CSRF exemption applies only to requests that send `Authorization: Bearer` and to the token-only MCP routes, so a mutating `/api/v1/*` call with neither a Bearer token nor `X-Requested-With` returns `403`. On the external maintenance routes an `Authorization` header is checked only as an API token and never falls back to the session cookie.
- **Edit API Tokens and Custom Scopes**: An **Edit** action in Settings > API & MCP Access renames a token, changes its scopes, or both, without creating a new token. The token string, expiry and usage history stay the same, so Vector, Fluent Bit, Home Assistant, MCP client and script configurations need no update, and the change applies to the token's next request (a legacy MCP SSE session closes when its token loses `logs:read`). The create and edit dialogs offer **Custom** next to the presets: a scope tree where a ticked category is saved as `<category>:*` and so covers actions added later. A warning appears before saving a change that adds access. A new **Home Assistant** preset (`system:read`, `maintenance:write`, `system:write`) matches the scopes the LogShed Home Assistant integration uses. New endpoint `PATCH /api/tokens/{id}` (web login only). A token name of only spaces is now refused (`422`), and the token list shows "Custom" for tokens that match no preset. A new [API Token Scopes Guide](docs/API_SCOPES.md), linked from the token dialog, explains each scope and preset.
- **Rate Limit Headers & OpenAPI Bearer Scheme**: Token-authenticated REST and ingestion responses return `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset`. Every `429` adds `Retry-After`, including MCP, login, AI and the prune and vacuum cooldowns. The OpenAPI document declares an HTTP Bearer security scheme so `/docs` offers an Authorize button.
- **HTTP Log Ingest (`POST /api/v1/ingest`)**: Push logs from scripts and edge shippers (Vector, Fluent Bit) with a token that holds `logs:write`. The body is a JSON array, a single object or NDJSON, with the fields `message`, `timestamp`, `severity`, `app_name`, `source_ip`, `source_alias` and `raw` (see the [HTTP Ingest guide](docs/SENDING_LOGS.md#http-ingest-api)). Timestamps are ISO 8601 or Unix epoch seconds or milliseconds (numbers, or strings of 10 or 13 digits); one that is unreadable, older than `MAX_RETENTION_DAYS` or more than 5 minutes ahead is replaced with the received time. The body is limited by `INGEST_MAX_BODY_BYTES` (5 MiB) and 10,000 entries (`413`); `message` and `raw` are cut to 64 KB and `source_ip`, `source_alias` and `app_name` to 255 characters; a request that uses LogShed's own identities (`source_ip` `docker` or `docker:*`, or `127.0.0.1` with alias `logshed`) is refused as a whole (`422`). Each record is stored as its own entry (indented lines or lines starting with "at ..." are never merged), an empty severity is stored as info (6), and ANSI and control characters are removed from the text. Drop rules and maintenance `drop_errors` sessions always apply and a full queue never blocks the request. The response is `{status, accepted, dropped}`. A revoked token stops working at once.
- **Model Context Protocol (MCP) Server**: Built-in server that lets external AI assistants (such as Claude Desktop, Cursor, Antigravity and Windsurf) investigate homelab issues. It exposes 8 tools (`get_system_metrics`, `list_services`, `query_logs`, `get_log_context`, `count_logs`, `get_recent_alerts`, `enable_maintenance`, `disable_maintenance`), 3 live resources (`logshed://system/metrics`, `logshed://services`, `logshed://alerts/active`) and two prompts (`investigate_incident` for incident triage and `safe_service_upgrade` for upgrades with a targeted `drop_errors` maintenance window). It is off by default (`LOGSHED_ENABLE_MCP`, or the switch in Settings > API & MCP Access) and answers `403` while off. Connecting needs only `logs:read` and each tool and resource checks its own scope (`alerts:read`, `system:read`, `maintenance:write`); new tokens default to a read-only "AI Assistant / MCP (Read Only)" preset, and "AI Assistant / MCP + Maintenance" adds the right to start and end maintenance windows. Tokens are sent in the `Authorization` header; `?token=` in the URL is refused unless `MCP_ALLOW_QUERY_TOKEN=true`, a supported opt-in for MCP clients that cannot send headers. `drop_errors` maintenance over MCP must name a `target_app` or `target_host`, the server instructions tell agents that log content is untrusted, and Settings > API & MCP Access shows a redaction notice while MCP is on. Legacy SSE sessions are bound to the token that opened them (revoking it closes its streams, and a message with a different token is refused). `disable_maintenance` returns `terminated_sessions`, `remaining_active_sessions`, `active` and `server_time`, and an unknown session id is an error. `get_system_metrics` returns `live_counters_available` and `udp_receive_errors`; over stdio the live ingestion counters are `null`. `list_services` reports `truncated: true` when its lists were capped at 500. Results use the same redaction as the REST API.
- **MCP Network SSE, Streamable HTTP, and Local Stdio Transports**: Streamable HTTP at `/mcp` (and `/api/v1/mcp`) for modern MCP clients, remote Server-Sent Events (`GET /api/v1/mcp/sse` + `POST /api/v1/mcp/messages`) authenticated with Bearer tokens or `mcp-proxy`, and a local Docker standard input/output transport (`python -m app.cli mcp`, with `--db-path`; maintenance changes made over stdio reach the web process within 30 seconds). Client configuration snippets use the `app_url` from Advanced settings.
- **Log Aggregation & Counting API (`GET /api/v1/logs/count`) and `count_logs` MCP Tool**: Token-efficient counts grouped by severity, application or source host, so assistants and scripts can check error volume without fetching log payloads. App and source groupings accept `group_limit` (default 25, max 200) and report `truncated` when more groups exist.
- **Collapsible Client Configuration Guides in Web UI**: Three accordion configuration snippets (Claude Desktop via remote `mcp-proxy`, Cursor / Windsurf / Antigravity via network SSE or Streamable HTTP, and Claude Desktop via local Docker stdio) with one-click copy buttons.
- **Dedicated MCP User Guide**: [`docs/MCP_GUIDE.md`](docs/MCP_GUIDE.md) with troubleshooting examples, client configurations and security guardrails.
- **Concurrent Maintenance Sessions & Error Dropping**: Overlapping API-driven and web UI maintenance windows, each with its own end, with two modes: `silence_alerts` suppresses notifications and `drop_errors` filters incoming error and critical logs during volatile maintenance. At most 20 sessions can be active (`409` beyond, even when started at the same moment from the web UI, REST API and MCP), target filters and reasons are limited to 255 characters, and stopping an unknown or already ended session returns `404`. A web UI window must end more than 30 seconds from now. Drop counts recorded in the 30 seconds before a shutdown are saved, and reading the status never writes to the database. The banner shows who started the window (Web UI, "MCP - <token name>", "MCP (local)" or the API token name), its Manage link opens the Maintenance tab (Scheduled window for schedule-only windows), and a failed health check shows a degraded indicator.
- **Maintenance Window Audit History**: Every on-demand maintenance session (web UI, API token, MCP) records an incident history entry with start time, end (or early-termination) time, trigger (UI, MCP, or "API - <token name>"), type, target app and host, and a count of dropped logs, shown in a maintenance view in the Rules & History tab and exposed through `/api/v1/alerts/history` and the `get_recent_alerts` MCP tool. Ended sessions follow log retention for pruning, and clearing alert history keeps the rows of windows that are still running.
- **Docker Container Label Aliasing & Display Resolution**: Priority-based resolution of Docker container display names (`app_name`) from custom labels (`logshed.alias`, `logshed.name`), Docker Compose service metadata (`com.docker.compose.service`), Swarm service attributes and raw container names, with chunked retroactive updates of historical log records that do not lock the table.
- **Configurable Rule Ordering for Drop Rules and Alert Rules**: User-configurable evaluation order for drop rules and alert rules, stored in schema version 3 (`display_order`) and set with `PUT /api/drop-rules/reorder` and `PUT /api/alerts/rules/reorder` (the list must name every rule once). Rules reload in memory without blocking the server.
- **Accessible & Drag-and-Drop Rule Reordering UI**: Desktop drag-and-drop with grip handles, and single-tap Up/Down chevron controls with touch-friendly targets on mobile. Fast clicks are sent one at a time and roll back to the last confirmed order on error.
- **Multi-Host Docker Collection (Remote Docker Daemons)**: A supervised `DockerCollectorPool` runs isolated `DockerTailer` tasks across several local and remote Docker daemons (Unix socket, plain TCP via `tecnativa/docker-socket-proxy`, or mutual TLS), with per-endpoint latency metrics, connection health and bootstrap support through `DOCKER_ADDITIONAL_HOSTS` (invalid JSON is ignored with a warning). Each host has its own on/off switch: turning off the local host (endpoint 1, the "Primary Docker" entry, also set by `ENABLE_DOCKER`) stops only that host, so LogShed can collect from remote hosts alone. Each host has a "Verify TLS host name" toggle (`verify_hostname`, on by default): the daemon certificate must match the host name, so a host reached by a bare IP address needs a certificate with that IP, or the toggle off for that host, and TLS to a host that is not on this machine requires a CA certificate. A `unix://` host URL must end in `docker.sock`, be the `DOCKER_HOST` socket or be listed in `DOCKER_ALLOWED_SOCKETS` (`422` otherwise). Link-local and cloud metadata addresses are refused when a host is saved and again each time LogShed connects, so a host name that later resolves to one (DNS rebinding) is refused and an error naming the host is logged.
- **Docker Endpoint Management & Connectivity Testing (`/api/docker/hosts`)**: Create, edit, delete and test Docker collection targets. TLS private keys (`client_key`) are write-only and encrypted at rest (responses show `has_client_key`), and "Test connection" reuses a host's stored keys and certificates only for that host's saved URL, never when the form marks them for removal, and returns only generic error text. The edit dialog can clear a stored CA or client certificate, a name that another host uses returns `409`, request fields have size limits, enabling or disabling host 1 starts or stops collection on every host straight away, and changing a host alias updates the labels on existing logs without slowing down on large databases. The collector's memory of renamed containers is capped.
- **Unified Sources Management Hub (`/settings/sources`)**: Syslog host aliases and configured Docker hosts in protocol-labeled cards with modal forms, plus automatic redirects from `/settings/aliases`. Docker collection switches, exclude patterns and source alias moved here from the Advanced tab.
- **Protocol-Aware Host Actions in Log Details**: Host management buttons in the log inspection drawer that tell Syslog and Docker sources apart (Edit Docker Host, Add or Modify Syslog Host Alias, or a guided reconfiguration for logs from the deleted local Docker host). Logs sent over HTTP ingest are never treated as Docker logs: they offer the host alias action and label their raw text "Raw Log Record".
- **Protocol-Decoupled Host Filtering & Facet Scoping**: Filtering, live streaming and facet discovery keep Docker container logs and Syslog host logs apart when both come from the same host IP address. Log facets and `list_services` hold at most 500 hosts and 500 apps and return `truncated` when anything was left out; the console shows a note when the host and app filter lists were capped.
- **AI Analysis Follow-up Conversations**: Ask follow-up questions about any AI diagnosis, below the Actionable Remediation card in the analysis modal or in a "Follow-up Discussion" section of Incident History (on-demand analyses and AI alert enrichments). Replies stream in live as Markdown with copyable code blocks, using the current AI settings with fallback model failover; follow-ups from the analysis modal use the provider, model and fallback order chosen for the diagnosis (`fallback_models` in the request, where an empty list means no fallbacks). Questions are redacted before dispatch, share the 10 requests per minute AI rate limit and are capped at 10 per analysis, with a turn counter, running token tally and a "Clear Thread" action. "Back to Preview" is disabled while a reply streams, and the stream stops when the discussion is closed. Threads are stored in a new `ai_conversation_messages` table and deleted with their analysis. New endpoints: `GET`/`DELETE /api/ai/audit/{audit_id}/messages`, `POST /api/ai/audit/{audit_id}/follow-up` and `POST /api/ai/audit/{audit_id}/follow-up/stream`.
- **Shorthand Query Filters**: Relative time bounds (`15m`, `1h`, `24h`, `7d`, `since_midnight`, `today`, `yesterday`) and named severities (`emergency`, `critical`, `error`, `warning`, `info`, `debug`) work across the web UI log routes, the REST API and MCP. `since_midnight`, `today` and `yesterday` start at midnight in the server time zone (`TZ`), with daylight saving handled. The console has a "Today" time preset, and links and saved views carrying `since_midnight` show it. Time presets (Last 15m, 1h, 6h, 24h, 7d, Today) are saved as relative times, so a saved view keeps meaning "the last hour".
- **UDP Loss Reporting**: `udp_receive_errors` in `GET /api/health` and `GET /api/v1/system/metrics` counts the UDP datagrams the kernel discarded because the socket receive buffer was full since the syslog listener started. The console navbar shows it as "UDP lost: N", separate from Dropped and hidden while it is 0 or unknown. Both Dropped and UDP lost count from when LogShed started and go back to 0 on restart, as their tooltips say. The count belongs to the network namespace (with `network_mode: host` it covers every UDP socket on the host) and is `null` when it cannot be read (not Linux, before the listener starts, stdio MCP).
- **Docs for UDP versus TCP and HTTP ingest**: [`docs/SENDING_LOGS.md`](docs/SENDING_LOGS.md) explains that UDP syslog can lose messages in bursts while TCP does not lose them in the kernel, how to raise `net.core.rmem_max`, and the HTTP ingest API with a `curl` example.
- **New Environment Variables**: `INGEST_MAX_BODY_BYTES`, `USER_REGEX_TIMEOUT_MS`, `MCP_ALLOW_QUERY_TOKEN`, `LOGSHED_ENABLE_MCP`, `DOCKER_ALLOWED_SOCKETS`, `DOCKER_ADDITIONAL_HOSTS`, `SYSLOG_MAX_TCP_CONNECTIONS_PER_IP` (default 20), `SYSLOG_UDP_RECEIVE_BUFFER_BYTES` (default 8 MiB) and `ENABLE_API_DOCS` (default `true`; `false` turns off `/docs`, `/redoc` and `/openapi.json`), all described in [`docs/CONFIGURATION.md`](docs/CONFIGURATION.md).
- **Contributor Files and CI**: A contribution guide (`CONTRIBUTING.md`), security policy (`SECURITY.md`) and code of conduct, issue forms for bug reports and feature requests, a pull request template, and a CI workflow that runs the frontend and backend test suites on pushes to `main` and release branches and on pull requests. Test tools are pinned in `backend/requirements-dev.txt`.

### Changed
- **Dependency Pins**: Backend dependencies are pinned to exact versions in `backend/requirements.txt` for reproducible builds. To update one, change its version in that file, run the full backend test suite (`.venv/bin/pytest backend/tests/ -q`), and build the Docker image before releasing. Transitive dependencies are not pinned.
- **Container Startup Warnings**: The entrypoint logs a warning when `PUID` or `PGID` is `0` (see the upgrade notes) and when the Docker socket is owned by group 0 (root). As in 1.2.x, the app user still joins the root group to read such a socket; the new warning recommends a Docker socket proxy such as `tecnativa/docker-socket-proxy` with `DOCKER_HOST=tcp://proxy:2375`.
- **Alert History Follows Retention**: The daily cleanup and manual purge now delete all alert history (alert firings, daily digests, on-demand analyses and maintenance windows) older than the configured retention, together with their linked AI audit records. Maintenance windows age out by their end time, and running windows are never deleted. Prune results report logs, history and AI audit records separately, and `GET /api/maintenance/prune/preview` returns the counts a prune would delete before anything is removed.
- **Retention Change Preview**: Lowering the retention period in the Storage panel shows which logs, history entries (by kind), AI audit records and old metric samples would be deleted, with the choice to save and delete now, save and delete at the next daily cleanup, or cancel. "Purge Expired Logs & History Now" shows the same preview and asks for confirmation (or reports that nothing is expired) before deleting, and the result banner reports logs, history entries and AI audit records separately. "Save and Delete Now" says when retention was saved but the purge was busy or failed.
- **Future Timestamp Window**: Log timestamps up to 5 minutes ahead of the received time are kept for every source (syslog, Docker and HTTP ingest). Syslog and the database writer used to reset them after 60 seconds.
- **UDP Syslog Receive Buffer**: The UDP syslog socket requests an 8 MiB receive buffer (`SYSLOG_UDP_RECEIVE_BUFFER_BYTES`, `0` keeps the OS default) instead of the OS default, which holds only a few hundred small messages. The startup log reports the size granted and warns, with the `net.core.rmem_max` fix, when the kernel capped it.
- **Multiline Entry Size**: A merged multiline entry is split into entries of at most 64 KB; the later parts keep the stream and the most severe level seen so far.
- **Rule Pattern Time Limit**: A rule whose pattern times out 20 times within 5 minutes is disabled automatically (see the upgrade notes).
- **Consolidated Docker Configuration into Sources Hub**: Docker collection switches, exclude container patterns and source alias settings moved from the Advanced Settings tab into the Configured Docker Hosts interface under Sources, keeping endpoint ID 1 in step with core system settings.
- **MCP and REST Token Efficiency & Compact Payloads**: `include_raw` defaults to `false` in `query_logs` and `get_log_context` (omitting duplicate raw syslog messages, facilities and ingest timestamps, which cuts context window usage by about 40 to 50%), `GET /api/v1/logs` and `GET /api/v1/logs/{id}/context` likewise omit `raw` unless `include_raw=true`, `fields: ["timestamp", "app_name", "message"]` projects only the named fields, and responses carry a human-readable `severity_label`.
- **API Tab Renamed to "API & MCP Access"**: API token management and the Model Context Protocol controls share one **API & MCP Access** tab in Settings (`/settings/api-tokens`).
- **Default-Off MCP Security Baseline**: The MCP master switch (`enable_mcp`) is off by default, and every MCP endpoint returns `403 Forbidden` until an operator turns it on.
- **Daily Digest Rollup**: Removed an unused query and the dead `sample_lines` field from `compute_daily_digest_rollup()`, which scanned up to 100 rows with a computed severity sort on every daily digest run.
- **Wider Internal Log Capture**: LogShed stores its own AI analysis, alerting, notification, retention pruning and storage metrics logs (subject to the Internal Log Severity Threshold), which were previously only written to the container output. Alerting, notification and AI logs are never evaluated by alert rules, so a rule cannot trigger itself through the logs its own firing writes; prune and storage metrics logs can be alerted on like any other log.
- **Modular Technical Specifications**: The monolithic `docs/SPEC.md` is split into domain modules under `docs/spec/` (`architecture.md`, `database.md`, `pipeline.md`, `ai-engine.md`, `security.md`, `api.md`, `frontend.md`, `deployment.md`), with `docs/SPEC.md` kept as a lightweight index.
- **Alert Rule Export and Import Routes**: The OpenAPI document lists `/api/alerts/rules/export`, `/api/alerts/rules/{id}/export` and `/api/alerts/rules/import`. The old `/api/alerts/export`, `/api/alerts/import` and `/api/alerts/{id}/export` paths still work as hidden aliases.
- **`reset-admin` Password Prompt**: `python -m app.cli reset-admin` asks for the new password twice and requires 8 to 128 characters. `--password` still works but prints a warning, because the value is visible in shell history and process listings. The README example is `docker exec -it <container> python -m app.cli reset-admin`.
- **Promote a Fallback Model**: The up arrow on the first fallback model swaps it with the primary model, in Settings and in the analysis modal, so a fallback no longer has to be removed before it can be chosen as the primary.
- **Database Indexes**: Three redundant indexes (`idx_alert_history_rule_id`, `idx_drop_rules_enabled`, `idx_alert_rules_enabled`) are no longer created and are removed from existing databases.

### Fixed
- **Prune and Vacuum Safety**: Prune and vacuum now share one in-progress lock across the web UI and the daily `PruneWorker`, so a manual prune can no longer overlap with another prune or a vacuum (concurrent attempts return `409`; the worker retries after 60 seconds). The lock stays held until the operation finishes, even if the client disconnects or the worker is stopped mid-prune. Vacuum and prune failures are logged server-side and return a generic message instead of exception text.
- **Storage Overview**: `GET /api/system/storage` reuses a storage snapshot for up to 15 seconds instead of counting every log row on each request. The 30-day trend chart places snapshots by time, so the extra snapshots that log deletion and compaction record no longer repeat hour labels or squash the time scale, and hours show as 09:00 rather than 9:00.
- **Internal Error Responses**: A notification test against a channel whose stored URL cannot be decrypted returns a generic `500` message (the error is logged server-side) instead of exception text. An unexpected failure in the alert pattern test (`POST /api/alerts/test`) likewise reports a generic error and logs the details.
- **Alert Rule Patterns with Backslashes**: Patterns such as `\bKilled`, `error \d+` or `foo\.bar` used to be compared as literal text, including the backslash, so those rules never fired. They now run as regular expressions (see the upgrade notes).
- **Login and AI Rate Limit Responses**: The `429` responses carry a `Retry-After` header.
- **Password Changes**: Changing the admin password (and first-run setup) runs its Argon2 work on the dedicated pool, so it cannot stall log searches, and a concurrent password change is refused with `409` instead of being overwritten.
- **Time Filters**: The web UI log filters and log deletion compare times in UTC, so a log stored exactly at a boundary is included and non-UTC offsets select the right window. Links with an absolute time show Custom in the Time selector.
- **Log Context**: The context of a log with no source alias shows only that host's lines, and `lines=1` returns one line on each side.
- **Log Search and Deletion**: A locked database during a web UI search, log deletion or delete preview returns `503` "database is busy" instead of empty results or a `500`.
- **Console, Live Stream and Saved Views**: The Filter button applies the current filters. Load failures, live-stream disconnects (with automatic retry and re-login after an expired session) and saved-view pin and delete failures are shown instead of being silent. Shift-click selection after deleting logs, the log count after deletes and downloads aborted in some browsers work correctly. Live stream timestamps follow the server time zone even before settings arrive, show the date again after midnight, and alert history times use the server time zone. The stream keeps the newest 3,000 rows while auto-scroll is on and up to 20,000 while you scroll back; new rows wait in the "N new" banner instead of trimming the history you are reading. Scroll position stays anchored when the layout switches between mobile and desktop while paused, applying a saved view loads logs once, and a newer search stops the request it replaces. The live stream no longer sends internal fields to the browser and pings idle connections every 15 seconds instead of every half second.
- **AI Diagnosis**: A failed or refused diagnosis stream no longer silently re-runs the whole analysis through the non-streaming endpoint, which doubled token cost and could save a duplicate audit record. Closing the analysis modal stops the running preview or diagnosis, so a late result cannot appear for other logs, and a model list that finishes loading (or fails) after the window was closed or reopened for other logs no longer fills or taints the new run. Diagnosis streams send a heartbeat every 15 seconds, so reverse proxies no longer cut long model calls. Gemini, OpenAI and Anthropic clients are closed after each request. Alert AI enrichment uses the configured AI timeout and thinking budget. Removing every fallback model in the analysis modal now means no fallbacks, instead of the saved fallback models being used. On small screens the analysis result header wraps instead of running off the screen when the Fallback badge is shown.
- **AI Model Refresh**: Refreshing the models of a provider with no base URL of its own no longer uses another provider's base URL, and a key typed during the refresh is no longer saved for a base URL that was not saved.
- **Blocking Redaction**: AI analysis (up to 200 log lines) and AI alert enrichment (up to 50) redact their log lines in a worker thread instead of on the event loop, so a large batch cannot stall the server.
- **Incident History**: The incident detail says "N matching logs", which is what the number counts.
- **Alert and Drop Rules**: Editing a drop rule can clear its host or app pattern (before, the save reported success but kept the old filter), and a failed drop rule save no longer resets the live drop counter. Alert rule create and update reject unknown rule types (`422`), and updating a rule that was deleted at the same moment returns `404` instead of `500`. A rule with an invalid regex is no longer re-checked on every log line. "Run Test" applies the rule's own app and severity filters and the severity lists offer all 8 levels. The "Systemd Session Chatter" drop preset matches only PAM systemd-user "session opened" and "session closed" lines (see the upgrade notes). The Drop Rules tab count no longer flashes 0/0, deleting the last history row on a page steps back a page, and the drop rule dialog's guide link opens the Ingestion Drop Rules section.
- **Settings Pages**: The "unsaved changes" bar no longer sticks for a keyless OpenAI-compatible provider. Unsaved edits on the Application tab survive switching tabs and saves made elsewhere, the Advanced tab warns about unsaved changes (Save and Continue saves them), and edits to an AI provider that is not selected count as unsaved. Emptying the AI API key field is applied with the normal Save instead of saving at once and discarding other edits. The AI base URL can be cleared, and per-provider base URLs must be http or https. Closing the Add Host Alias dialog opened from the log view no longer reopens it on the next visit to Settings. Settings and Storage reload from the server when opened. Errors while applying syslog or Docker settings are logged. The AI Engine Limits note on the Advanced tab says the timeout applies to every provider and the thinking budget to Gemini and Claude models.
- **Notifications and Digest**: "Send Digest Now" says when the digest was saved to History but delivery failed. Deleting the notification target chosen for the daily digest clears the digest target setting, and the target delete confirm ignores repeat clicks. Turning the daily digest on, or changing its schedule time, no longer sends a digest within 30 seconds when that time has already passed today (which gave two digests close together after "Send Digest Now"): the first digest is the next occurrence of the schedule time, so tomorrow if today's has passed. A digest missed because LogShed was down still goes out when it starts again that day, saving other settings changes nothing, and installs upgraded with the digest on send as before.
- **Syslog and Docker Hosts on One Machine**: Filtering, live streaming, facets and scoped deletion no longer mix a machine's syslog logs with the container logs of a Docker host on it. Before, a Docker host's name, or a Docker alias that differed from the syslog alias only in letter case, pulled both kinds of log into one filter (and one deletion). A syslog alias and a Docker host alias can no longer share a name (letter case ignored, `409`), a syslog hostname that matches a Docker host alias is not used as the host label (the IP is kept), and clearing a Docker host's alias stores `docker`.
- **Maintenance Schedules and Daylight Saving**: Recurring maintenance windows follow the daylight saving rules of the server time zone (`TZ`, or `/etc/localtime` when `TZ` is unset). Before, every window was worked out with the current UTC offset, so after a clock change the next window was shown an hour off (a Sunday 02:00 window read 01:00 in the week before the clocks went back) and a window spanning the change ran an hour short or long. A start time in the hour skipped when the clocks go forward begins an hour later, and one in the hour repeated when they go back begins at its first occurrence.
- **Local Times Around a Clock Change**: AI analysis prompts give each log the local time in force at its own moment, and the Timeline Reference shows both UTC offsets when the clocks changed during the selected logs. Before, one offset (taken when the page was loaded) was applied to every log, so after a daylight saving change older logs were shown an hour off. The log details drawer marks each timestamp with its UTC offset (for example `UTC+01:00`) instead of the current zone abbreviation, which was wrong for logs from the other side of a change and stayed out of date until the page was reloaded. `/api/settings` reports `server_timezone` as an IANA zone name, or `null` when the server zone has none (`TZ` unset with a non-UTC `/etc/localtime`), and the UI then shows browser time. Before, it could report an abbreviation such as `BST`, which browsers read as Bangladesh time.
- **Docker Collection**: Docker containers that write without newlines (non-TTY) are split into 64 KB entries instead of growing an unbounded buffer.
- **Dropped Log Count**: Internal LogShed logs dropped because the queue is full count towards the dropped logs total.
- **Syslog**: If the syslog port is in use at startup, LogShed retries with backoff instead of running with no listener. Shutdown no longer hangs while TCP senders such as rsyslog are connected. Messages already received but not yet parsed are processed at shutdown instead of being thrown away, and messages already received from a TCP sender that disconnects normally (such as an rsyslog restart) are stored instead of being lost.
- **Full-Text Index**: The indexer takes the write lock before reading its position, so it can no longer index the same logs twice when it runs together with a prune, delete or shutdown drain. Index compaction after a prune or large delete runs in short steps, so ingestion no longer stalls behind one long index rewrite. A cancelled indexing pass keeps its database connection open until its worker thread finishes, so stopping LogShed no longer risks a crash.
- **Background Worker Restarts**: A worker that crashes after running for at least a minute restarts after 1 s again, instead of waiting out the backoff built up by earlier crashes.
- **Docker First Log Lines**: The first lines a container writes after it starts are no longer lost. LogShed reads a container that starts or restarts while it is running from the moment of its start event; containers already running when LogShed starts are still read from the end of their log.

### Security
- **Regex Denial of Service**: Alert and drop rule patterns run on the `regex` package with a real per-match time limit (50 ms). In 1.2.1 the time limit could not stop a match that was already running, so one bad pattern could freeze ingestion. Saving a rule also refuses more backtracking-prone patterns. See the upgrade notes.
- **Redactor**: It catches secrets in JSON and quoted keys (`{"password":"..."}`, single quotes, escaped JSON inside log messages, quoted values with spaces), Cookie and Set-Cookie headers, Discord webhook URLs, Telegram bot tokens, Google API keys, Stripe live keys, GitLab and GitHub fine-grained tokens, encrypted and PGP private keys, and signed-URL `sig=` and `signature=` parameters. It runs in linear time on hostile input: crafted syslog messages (repeated `-----BEGIN PRIVATE KEY-----`, `http://`, `eyJ-` or `sshpass` runs) could previously stall the process for seconds to minutes during alert firing, API responses or AI prompts. Any single input longer than 500,000 characters is cut at a line break and marked truncated. A private key split across separate syslog messages is still not caught, because the redactor sees one message at a time.
- **Login Rate Limiting**: Each attempt is counted before the password is checked, so many parallel guesses can no longer get around the limit (1.2.1 counted only failures after the check). The limit is 5 failures per minute per client address, IPv6 clients share one limit per /64, only 2 attempts per address are checked at the same time, and a successful login clears the count. Exceeding a limit returns `429` with `Retry-After`. Password checks run on their own small worker pool, so a login burst cannot stall log searches. LogShed logs a warning at startup while `trust_docker_proxies` is on, because every address in `172.16.0.0/12` may then set `X-Forwarded-For` and spoof its address; prefer `TRUSTED_PROXIES=<reverse proxy container IP>`.
- **API Documentation Access**: `/docs`, `/redoc` and `/openapi.json` need the web login (see the upgrade notes). Swagger UI and ReDoc are served by LogShed itself under a strict content policy (the one inline start-up script is allowed by its hash), with no CDN, no Google Fonts and no request to the online validator, so no third-party script runs on LogShed's address.
- **Docker Address Check**: Docker connections, including a `tcp://` `DOCKER_HOST`, check the address actually connected to, and refuse link-local and cloud metadata addresses even when a host name resolves to one later (DNS rebinding).
- **Syslog and Query Limits**: One source IP can hold at most 20 TCP connections, and syslog messages over 65,536 characters are cut. The web UI log list and stream refuse more than 500 `source` or `app_name` values (`422`), and at most 20 live log streams can be open at once (`503` beyond).
- **Container Hardening**: The container sets `umask 027` so database files are not world-readable, and `reset-admin` requires 8 to 128 characters.
- **HTTP Headers, CORS and Version Endpoint**: Every response carries a Content-Security-Policy, API responses are sent with `Cache-Control: no-store`, and CSRF rejections carry the security headers. `CORS_ORIGINS=*` is ignored with an error, `DEBUG` no longer trusts localhost origins, and cross-origin requests may send only the headers LogShed uses. `/api/system/version` shows no version to anonymous callers and starts no update check for them, and a failed GHCR check is retried at most once a minute.
- **Notification and AI Provider Safety**: Notification delivery checks the address it actually connects to against the blocked ranges (stopping DNS rebinding), and self-hosted hosts of plugins such as `notica://` are validated. With `HTTP_PROXY`, `HTTPS_PROXY` or `ALL_PROXY` set (any letter case), notifications go through the proxy, which may be on a loopback or private address; destinations reached through it are checked when the channel is saved and before each send, but DNS rebinding protection for them then depends on the proxy (LogShed logs this once), and destinations in `NO_PROXY` keep the connect-time check. The channel test resolves DNS off the event loop, errors are logged with URLs and secrets masked, and several channels for one alert are sent one after another. Changing an AI provider's base URL without entering a new key clears the stored key, and the model refresh no longer sends the stored key to a different base URL; the refresh endpoint redacts provider error text in its response and in the server log.
